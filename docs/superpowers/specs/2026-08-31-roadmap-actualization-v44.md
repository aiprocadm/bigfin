# Bigfin — Дорожная карта v44 «Правило, которое обходится» — 2026-08-31

Карта v43 отправлена (#368) и ждёт вливания. Эта карта закрывает находку,
которую v43 записала в задел: **сторож «выключенный раздел объясняет себя»
обходится переменной**. Ветка растёт от ветки v43 — обе трогают
`DealsPage`.

Поручение владельца: «прими решение самостоятельно и продолжай по ТЗ».

---

## 1. Что дала разведка

### Находка 1. Два экрана снова гаснут в пустоту

Карта v36 закрыла правило «раздел за флагом модуля объясняет себя, а не
гаснет»: `return null` заменён на экран `ModuleDisabled` **на 21 экране**, и
поставлен сторож `moduleDisabledSpeaks`.

Сторож ищет запись вида:

```ts
if (!featureCan(Features.Acquiring)) return null;
```

Но «Сделки» и «Финмодель» написаны иначе — флаг сперва кладут в
переменную:

```ts
const canDeals = featureCan('deals');
...
if (!canDeals) return null;
```

Для человека это то же самое, для сторожа — нет. Замер по всем экранам
раздела:

| Способ погасить экран | Сколько |
|---|---|
| прямой вызов внутри условия (сторож видит) | **0** |
| флаг положен в переменную (сторож не видел) | **3** |
| тернарник `? … : null` | 0 |
| пустой фрагмент `<></>` вместо `null` | 0 |

Из трёх найденных два — экраны: «Сделки» и «Финмодель». Третий —
кнопка-колокольчик в верхней панели, её прятать правильно.

### Находка 2. Дыра могла быть шире — оказалась нет

Проверено, нет ли второй половины беды: экранов **за флагом**, которые
флаг не проверяют вовсе (тогда при выключенном модуле человек увидит не
объяснение, а ошибки сервера).

Замер: пунктов меню за флагом **25**, экранов, не проверяющих свой флаг, —
**0**. Здесь продукт здоров.

### Находка 3 (в задел). Так обходится не только этот сторож

Сторожа проекта читают исходники и ищут в них **текст**. Любой такой
сторож обходится переименованием — ровно как случилось здесь.

Замер: сторожей, читающих исходники, **29**; из них проверяют наличие
текста **14**, и таких проверок **34**. Это не значит, что все они дырявые,
— значит, что каждый заслуживает вопроса «а если написать то же самое
другими словами?».

В эту карту не беру: нужен разбор каждого сторожа по отдельности.

## 2. Фаза «Правило, которое обходится» — срезы

1. **С1 — сторож видит флаг, положенный в переменную**, и два погасших
   экрана снова объясняют себя.
2. **С2 — правило закрывает и остальные ходы** (тернарник в обе стороны),

## 3. Что сделано

### С1 — сторож видит флаг в переменной

Правило вынесено в отдельную функцию `goesBlank` и проверяется дважды:
прямой вызов внутри условия — и любая переменная, в которую положили
`featureCan(...)`.

«Сделки» и «Финмодель» показывают `ModuleDisabled` — тот же экран, что и
остальные 21: заголовок, объяснение и кнопка «Открыть настройки модулей».

Появился **явный список исключений** `HIDDEN_ON_PURPOSE` — по образцу
`UNLINKED_MODULE_ROUTES` из проверки достижимости страниц. В нём одна
строка: кнопка-колокольчик в верхней панели. Прятать её правильно — человек
в этот момент стоит на работающем экране, и объяснение на месте кнопки
выглядело бы поломкой шапки. Отдельный тест следит, что исключение не
переживёт сам файл и не ослабит проверку молча.

### С2 — правило закрывает и остальные ходы

Добавлены тернарник (`return canX ? <Page /> : null`) и его перевёрнутая
запись. Файлов с такими записями сегодня нет — правило укрепляется наперёд:
один обход уже случился и стоил двух погасших экранов, поэтому закрывать
стоит все ходы, а не только тот, что нашли.

### Проба самого правила

Правило проверено не только на файлах продукта, но и на образцах — иначе
оно зеленело бы «бесплатно»:

| Образец | Правило |
|---|---|
| `if (!canDeals) return null` (флаг в переменной) | **видит** |
| `return canDeals ? <DealsList /> : null` | **видит** |
| `return !canDeals ? null : <DealsList />` | **видит** |
| `if (!canDeals) return <ModuleDisabled />` (исправный экран) | молчит |

И на самом продукте: до правки проверка краснела списком из двух экранов,
после — зелёная.
