# ㉛ МойСклад: импорт товаров с себестоимостью — дизайн

Дата: 2026-08-03. Дорожная карта v5 §5 п. 6, подпункт ㉛ («синхронизация
закупок/себестоимости и отражение в учёт — не доделано»).

## 1. Что есть

Модуль `MoySklad` (флаг `moysklad`): подключение по токену, тонкий клиент
JSON API `remap/1.2`, маппинг товаров и отгрузок в превью-формат
(`mapMoysklad.ts`, покрыт тестами) и **read-only превью** — посмотреть
списком и всё. В карточки Bigfin ничего не попадает.

Важно: контракт API здесь **уже проверен** предыдущей работой (клиент и
маппинг написаны и используются), в отличие от Альфа-Банка и Ozon, где
спецификация была недоступна.

## 2. Цель и рамки

Перенести справочник товаров из МойСклад в Bigfin вместе с **себестоимостью**
(`buyPrice`) и ценой продажи (`salePrices[0]`), чтобы не заводить карточки
руками и чтобы себестоимость приходила из системы, где её ведут.

**В объёме:** предпросмотр (что создастся/обновится), импорт товаров,
идемпотентность по идентификатору МойСклад, страница с кнопками.

**Вне объёма:** импорт документов продаж и закупок в учёт (это отдельная
задача с проводками), остатки, синхронизация в обратную сторону, авто-обмен
по расписанию.

## 3. Идемпотентность

Тенантная миграция `create_moysklad_import_links`:

| колонка | смысл |
|---|---|
| `entity_type` | `item` (задел под будущие типы) |
| `external_id` | `id` сущности МойСклад |
| `entity_id` | id карточки Bigfin |

Уникальный индекс `(entity_type, external_id)` — как у `onec_import_links`
и `crm_sync_links`.

**Замеченный долг:** это третья таблица-связка одинаковой формы. Просится
одна общая с колонкой «источник», но объединение затронуло бы две уже
работающие интеграции — выношу отдельной задачей, здесь следую образцу.

Сопоставление при импорте:
1. связь по `(item, external_id)` → обновляем карточку;
2. связи нет, но нашёлся товар с тем же **артикулом** (`code`) → привязываем
   к нему и обновляем;
3. иначе создаём новый товар и связь.

Обновление не затирает заполненные поля пустыми значениями из МойСклад.

## 4. Что переносится

| МойСклад | Bigfin |
|---|---|
| `name` | наименование |
| `code`/`article` | артикул (`code`) |
| `buyPrice.value` (копейки) | **себестоимость** (`costPrice`) |
| `salePrices[0].value` (копейки) | цена продажи (`sellPrice`) |

Товары создаются с `type: 'service'` и без флагов продажи/закупки — как в
импорте CommerceML: счета учёта из МойСклад неизвестны, пользователь
дозаполнит их при первом использовании. Цены при этом сохраняются.

## 5. API и фронт

- `GET /moysklad/import/preview` → `{ toCreate, toUpdate, sample[] }`;
- `POST /moysklad/import` → `{ created, updated, skipped }`.

Оба под правом `manage all` и за флагом `moysklad`.

На странице МойСклад — блок «Импорт товаров»: «Проверить» (показывает, что
произойдёт, и первые строки с ценами) → «Импортировать». Ключи i18n
`moysklad.import.*` парно en/ru.

## 6. Тестирование

- Импорт на заглушках: создание с себестоимостью, повторный импорт
  (обновление, не дубли), подхват существующего товара по артикулу,
  отсутствие затирания заполненных полей пустыми, товар без имени пропускается.
- Предпросмотр ничего не пишет.
- Миграция — прогон up → down → up на клоне тенантной БД стенда.
- Живой импорт требует токена МойСклад (ручная приёмка владельцем);
  сервис проверяется против заглушки клиента API.

## 7. Порядок работ

1. Миграция связей + модель.
2. Сервис предпросмотра/импорта + тесты.
3. Эндпоинты + прикладной слой.
4. Фронт: блок импорта, хуки, i18n.
