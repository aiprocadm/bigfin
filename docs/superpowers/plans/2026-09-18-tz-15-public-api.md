# ТЗ, этап 15 «Публичный API и вебхуки» — план и приёмка

Этап целиком про то, что **наружу отдаётся ключ от всех денег организации**.
Поэтому почти каждое правило здесь написано, исходя из двух допущений: база
однажды утечёт, и адрес вебхука однажды узнают.

## Что сделано

### Токены

| Правило | Почему |
|---|---|
| В базе только отпечаток (sha256), самого токена нет нигде | утечка базы иначе отдала бы доступ ко всем организациям сразу, и отозвать токены никто бы не успел |
| Токен показывается человеку **один раз** | «покажите ещё раз» означало бы, что он лежит в базе целиком |
| Сравнение постоянного времени (`timingSafeEqual`) | обычное сравнение выходит на первом различии, и по времени ответа токен подбирается посимвольно |
| **Пустой список прав — это НЕ «можно всё»** | токен, у которого забыли проставить права, не должен получать их по умолчанию |
| Незнакомое право выбрасывается при сохранении | опечатка `reports:raed` иначе осела бы в базе и выглядела как выданное право: в списке есть, а работать не будет никогда |
| Испорченный JSON прав читается как пустой список | «не смогли разобрать» — это не «ограничений нет» |
| Отзыв, а не удаление | удалённый токен исчезает из журнала вместе с ответом на вопрос «кто и когда им пользовался» — а его задают как раз после утечки |
| Повторный отзыв не сдвигает дату | она отвечает на вопрос «когда перестал работать» |
| Наружу всегда один и тот же отказ | разные ответы («истёк» против «не существует») сообщают перебирающему, что он угадал строку |
| Токен без срока жизни допустим | ТЗ требует «срок жизни», а не «обязательный срок»; навязанный срок ломал бы интеграции молча |

Права разделены на чтение и запись по каждому разделу. Единственного
выключателя «полный доступ» нет намеренно: с ним у интеграции, которая только
забирает отчёты, не было бы выбора между «ничего» и «всё».

### Вебхуки

| Правило | Почему |
|---|---|
| Подписывается **тело вместе со временем** | иначе подпись годится навсегда и перехваченный вызов можно повторять бесконечно |
| Подпись старше 5 минут отвергается, даже будучи верной | то же самое |
| Нечисловое время — отказ | `Math.abs(NaN) > 300` — это «нет»: проверка свежести пропустила бы что угодно, притворяясь рабочей |
| Внутренние адреса запрещены | вебхук делает **наш** сервер по адресу, который назвал пользователь; без запрета можно заставить сервер сходить на `169.254.169.254` и получить ключи машины |
| 4xx не повторяем (кроме 408 и 429) | «твой запрос неверен» не станет верным от повтора — мы просто будем долбить чужой сервер |
| Задержка удваивается | ровные повторы добивают получателя, который и так лежит |
| Журнал доставок хранится | иначе на вопрос «почему мне не пришло событие?» ответить нечем |

### Где что лежит

`api_tokens` — в **системной** схеме, `webhooks` и `webhook_deliveries` — в
**тенантной**. Это не оплошность: токен приходит один, без указания
организации, — по нему организацию ещё только предстоит найти. Лежи таблица
токенов в базе организации, пришлось бы обходить базы всех организаций подряд
на каждый запрос. Подписка же принадлежит одной организации: её адрес, её
события, её секрет.

### Документация

Swagger UI на `/api/docs`. Флаг устроен так, что **молчание означает
закрыто**: на бою документация открывается только при `API_DOCS_ENABLED=true`.
Обратное правило («открыто, пока не выключили») однажды выставило бы наружу
полный перечень ручек боевого сервера просто потому, что при разворачивании
забыли дописать переменную. Старый адрес `/swagger` оставлен рядом и подчинён
тому же флагу — чужие закладки не рвутся.

Руководство с примерами на curl и на TypeScript SDK — `docs/public-api.md`.

## Мутация

Проверено на двух главных правилах:

- «пустой список прав = можно всё» → 1 тест красный;
- снят срок годности подписи → 1 тест красный.

Обе защиты возвращены, прогон зелёный.

## Найдено по ходу

Автоматическая проверка безопасности подсказала настоящую дыру, которой в
исходном замысле не было: при нечисловом времени `Math.abs(NaN) > 300` даёт
«нет», то есть проверка свежести подписи молча пропускала бы что угодно.
Закрыто явной проверкой `Number.isFinite` и отдельным тестом.

Сторож `settingsReadOnLoadGuard` покраснел на чтении `process.env` в значении
параметра по умолчанию. По духу правила это не нарушение (значение по
умолчанию вычисляется в момент вызова, когда `.env` уже прочитан), но
сторож этого не различает. Сторож **не ослаблялся**: чтение перенесено в тело
функции, где оно и без того нагляднее.
