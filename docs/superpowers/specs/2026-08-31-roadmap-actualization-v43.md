# Bigfin — Дорожная карта v43 «Разделы, в которых нельзя найти» — 2026-08-31

Карты v41 (#366) и v42 (#367) закрыты и влиты. Эта карта берёт главный
задел, который v39 оставила поиску и который v41 перечислила поимённо:
**новые разделы поиску неизвестны**.

Поручение владельца: «прими решение самостоятельно и продолжай по ТЗ».

---

## 1. Что дала разведка

### Находка 1. В этих разделах найти нельзя ничего — вообще

Замер по маршрутам: корневых разделов **45**, вид записей для поиска
объявляют **18**, молчат **27**. Из молчащих больше половины — экраны
настроек и отчётов, где искать нечего (интеграции, ставки НДС, сверки).
Остальные — списки записей.

Второй замер отвечает на главный вопрос: а есть ли у этих разделов своё
поле поиска на экране? Проверены «Сделки», «Заявки на оплату», «Основные
средства», «Долги», «Кредиты» — **ни в одном** файле страницы нет ни
одного упоминания поиска.

То есть найти запись в этих разделах нельзя **никак**: ни в шапке, ни на
самой странице. Единственный способ — глазами по списку.

### Находка 2. У этих списков нет общей машинерии

Классические разделы ищут через `DynamicListing` — там и роли поиска, и
соединения (карта v41). Новые разделы написаны простыми запросами: у
сделок фильтр по состоянию, у основных средств вообще нет параметров.
Общей машинерии нет, и без неё каждый раздел завёл бы свой поиск по-своему.

### Находка 3. У найденного некуда открыться

У документов есть выдвижная карточка, и поиск открывает её по номеру. У
новых разделов записи открываются **прямо на странице** через её
внутреннее состояние (`openDeal`, `selectedId`), а у заявок карточки нет
вовсе — реестр показывает их списком.

Значит мало научить поиск находить: надо ещё довести человека до
найденного. Иначе он попадёт в общий список и будет искать глазами второй
раз — ровно то, от чего уходили.

### Находка 4 (в задел). Сторож «выключенный раздел объясняет себя» обходится

Замечено попутно, в `DealsPage`:

```ts
const canDeals = featureCan('deals');
...
if (!canDeals) return null;
```

Сторож `moduleDisabledSpeaks` (карта v36) ищет `if (!featureCan(...)) return null`
и такую запись **не видит**: флаг положили в переменную. Экран снова гаснет
в пустоту — то, что карта v36 закрывала на 21 экране.

В эту карту не беру: тема другая, а замер по всем экранам надо делать
отдельно. Записано в задел.

## 2. Фаза «Разделы, в которых нельзя найти» — срезы

1. **Р1 — общий поиск по ключевому слову.** Один помощник на все списки без
   `DynamicListing`, чтобы следующий раздел стоил строку.
2. **Р2 — сделки ищутся по названию.**
3. **Р3 — заявки на оплату ищутся по назначению.**
4. **Р4 — основные средства ищутся по названию.**
5. **Р5 — найденная запись открывается**, а не теряется в списке.

Взято три раздела из девяти — те, где список растёт быстрее всего: заявку
заводят на каждый платёж, сделки и объекты копятся годами. Остальные шесть
(кредиты, долги, зарплата, дивиденды, бюджеты, платёжный календарь) —
в задел: там записей единицы или десятки, и глазами их видно.

## 3. Что сделано

### Р1 — общий поиск по ключевому слову

`applyKeywordSearch(builder, columns, keyword)` — одно условие на все
списки. Что важного внутри:

- **условие обособлено скобками.** Без них «или» из поиска склеилось бы с
  фильтром по состоянию: `(статус = X И имя) ИЛИ описание` — и раздел
  показал бы чужие записи;
- **знаки подстановки экранируются.** Иначе «100%» превращается в «найди
  всё», а «_» — в «любой символ»;
- **пустой запрос ничего не фильтрует** — пробелы тоже считаются пустотой;
- **тип строителя запроса узкий** (нужен только `where`/`orWhere`): списки
  разделов написаны и на Objection, и на голом Knex, и общий помощник не
  должен выбирать за них библиотеку. Первая редакция была прибита к типу
  Knex — проверка типов это и поймала.

Колонки поиска раздел объявляет у себя (`static get searchColumns()`):
сделка ищется по названию, заявка — по назначению платежа, объект — по
названию.

### Р2–Р4 — три раздела ищутся

Поиск проведён до конца по обеим сторонам: запрос принимает контроллер
(параметр `keyword` в описании запроса), применяет список, а витрина знает
вид записей, адрес, разбор ответа и привязку к окну поиска.

Тесты сервисов не проверяют «был ли вызов»: внутрь поддельной модели
подставлен **настоящий** строитель запроса, и проверяется живой SQL — в том
числе то, что фильтр по состоянию не размыт поиском.

### Р5 — найденная запись открывается

Выбор в поиске ведёт на страницу раздела и передаёт находку адресом:
`/deals?open=12`. Страница читает номер общим помощником `openIdFromSearch`
и открывает запись:

- **сделки** — раскрывают карточку найденной сделки;
- **основные средства** — раскрывают карточку объекта;
- **заявки** — своей карточки не имеют, поэтому найденная заявка
  **выделяется в реестре** и экран прокручивается к ней.

Закрытие карточки убирает номер из адреса — иначе карточка, открытая
поиском, возвращалась бы сразу после закрытия.

Мусор вместо номера (`?open=abc`, `?open=-3`) считается отсутствием: иначе
страница открыла бы запись «NaN» и показала пустую карточку вместо списка.

### Живая проба

Своя временная база (`mysql:8.0`, порт 3398, удалена после пробы), таблица
сделок с четырьмя записями. Выполнены запросы, которые строит помощник.

| Что проверял | Результат |
|---|---|
| «ремонт» строчными буквами | **2** — «Ремонт офиса», «Ремонт цеха» (регистр не мешает) |
| «ремонт» + состояние «в работе» | **1** — «Ремонт офиса» |
| то же **без скобок** (как было бы при ошибке) | **2** — вернулась и завершённая сделка |
| «100%» с экранированием | **1** — «Скидка 100% партнёру» |
| «100%» **без экранирования** | **2** — добавилась «Скидка 1000 рублей» |

Первая попытка пробы дала ноль находок на «ремонт»: данные записались в
испорченной кодировке, потому что клиент базы вызывался без
`--default-character-set=utf8mb4`. Проверено, что дело в измерителе, а не в
продукте (урок карты v35), и проба переделана.

### Задел

- **Шесть разделов из девяти** ещё не ищутся: кредиты, долги, зарплата,
  дивиденды, бюджеты, платёжный календарь. Механизм готов — каждый теперь
  стоит колонки в модели, параметра в описании запроса и четырёх строк на
  витрине.
- **Сторож модулей обходится переменной** (находка 4): нужен замер по всем
  экранам и починка правила.
