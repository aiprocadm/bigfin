# ТЗ, этап 14 «ИИ-чат по финансам» — план и приёмка

ТЗ: делается **только после этапа 13** и ограничения §13.1 действуют
полностью. Этап 13 закрыт по коду, его правила приватности и проверки чисел
переиспользованы целиком — своих копий заведено не было.

## Главная мысль этапа

Здесь та же опасность, что у выводов аналитика, только острее: человек
**спросил** и ждёт число. Ответ «на рекламу ушло 340 000 ₽» он примет как
факт и не пойдёт сверять с отчётом — ради того и спрашивал.

Поэтому:

- модель **не получает доступ к базе** — только перечисленные инструменты,
  каждый из которых зовёт существующий отчёт;
- каждое число ответа сверяется с тем, что вернули инструменты;
- не сошлось — **ответ не показывается вовсе**, не «показываем с оговоркой»:
  оговорку человек не прочитает, а число запомнит.

## Что сделано

| Правило | Почему |
|---|---|
| Перечень инструментов закрытый, «произвольного запроса» нет | он свёл бы на нет весь смысл: модель снова получила бы доступ к данным напрямую |
| Неизвестный инструмент **отвергается, а не угадывается** | догадка «она имела в виду ОПиУ» однажды подставит не тот отчёт, и ответ будет уверенным и неверным |
| Причина отказа уходит обратно модели | «инструмента get_revenue нет» она понимает и исправляется; молчаливый отказ заставил бы её выдумать ответ |
| Лишний параметр отвергается, а не отбрасывается | модель думает, что сузила запрос («только по рекламе»), а получила бы весь отчёт и приняла его за ответ на суженный вопрос |
| Несуществующая дата (`2026-02-31`) не проходит | JS молча превратит её в 3 марта, и отчёт посчитается не за тот период |
| Перепутанные даты не проходят | отчёт вышел бы пустым, а модель сказала бы «за этот период ничего не было» — и это звучало бы как факт |
| Период ограничен тремя годами | такой запрос почти всегда ошибка разбора даты, а не настоящее желание |
| Число из **вопроса** не считается выдумкой | «в 2026 году» — эхо вопроса, а не утверждение модели |
| Ответ без ссылки не показывается | ТЗ: «ответ всегда сопровождается ссылкой на отчёт»; ответ без источника нечем проверить, а значит, и оспорить |
| Неразобранный шаг = пустой ответ, а не вызов инструмента | догадываться, что она имела в виду, — путь к уверенному ответу по не тому отчёту |
| Ответ важнее инструмента, если пришло и то и другое | иначе разговор зациклился бы |
| Не больше 4 кругов | без предела модель, не сумевшая подобрать параметры, крутилась бы по кругу, и каждый круг платный |
| Результат инструмента проходит проверку приватности | он идёт **обратно в модель**, то есть наружу; отчёт мог бы принести с собой название контрагента |
| У чата НЕТ своего выключателя | два выключателя одного и того же ИИ — два места, где можно забыть выключить отправку данных |

### Почему ручка вопроса открыта по правам

`POST /ai-chat/ask` помечен POST только потому, что вопрос — это текст, и его
отправляют телом запроса. Ручка **ничего не меняет**: она читает те же отчёты,
что человек и так видит на экране. Требовать право на запись значило бы, что
вопрос о своих же цифрах доступен меньшему числу людей, чем сам отчёт.
Внесено в список `OPEN_BY_DESIGN` сторожа `writeEndpointsCoverage.spec.ts`
с этим обоснованием — сторож не ослаблен, решение записано.

## Мутация

- Неизвестный инструмент подменён первым доступным → 2 теста красные.
- Снята сверка чисел в ответе → 2 теста красные.

Обе защиты возвращены, прогон зелёный.

## Приёмка этапа 14

| Требование ТЗ | Состояние |
|---|---|
| Модель не имеет доступа к базе | ✅ только инструменты |
| Каждый инструмент — вызов существующего API отчётов | ✅ своего расчёта нет ни одного |
| Модель формулирует ответ по возвращённым агрегатам | ✅ |
| Ответ всегда со ссылкой на отчёт | ✅ без ссылки не показывается |
| Ограничения §13.1 действуют полностью | ✅ те же модули, не копии |
| Вопросы из ТЗ покрыты инструментами | ✅ расходы по статьям, прибыльность проектов, кассовые разрывы |
| Экран чата | ❌ остаток |
| Инструменты ДДС, Баланса и кассовых разрывов подключены к своим отчётам | ❌ остаток |

## Остатки этапа 14

| № | Что | Почему |
|---|---|---|
| Ч1 | Экран чата на витрине | ручки `GET /ai-chat/tools` и `POST /ai-chat/ask` готовы |
| Ч2 | `get_cash_flow`, `get_balance_sheet`, `get_cash_gaps` возвращают пустой результат | в этих отчётах строка означает ОСТАТОК, а не оборот; подставить под них свёртку статей нельзя — числа сошлись бы по форме и разошлись по смыслу. Сейчас честно отвечают «данных нет», и модель переспрашивает человека вместо того, чтобы выдумать цифру |
| Ч3 | Разговор без памяти: каждый вопрос начинается заново | «а в прошлом году?» пока не поймётся; хранение переписки — отдельное решение о том, где лежат вопросы человека |
| Ч4 | Живого вызова провайдера не было | нужны ключи владельца (тот же остаток И4 этапа 13) |
