## 1. Что дала разведка

Разведка пошла по отчётам: их в меню семнадцать, а открывал я до сих пор
один. Первый же щелчок дал находку, которая оказалась крупнее отчётов.

### Линия 1 (главная). Шесть пунктов меню уводят на главную

Открываю «Оборотно-сальдовая ведомость» — и оказываюсь на главной
странице. Без ошибки, без объяснения, без следа. То же с «Журналом»,
«Главной книгой», «Ручными проводками», «Созданием проводки» и
«Блокировкой операций».

Причина не в поломке, а в **потерянном правиле**. У продукта есть два
режима интерфейса: «Бизнес» (для предпринимателя) и «Бухгалтер». В режиме
«Бизнес» шесть чисто-бухгалтерских экранов намеренно скрыты — маршрут
уводит на главную:

```ts
if (isAccountantOnlyHidden(mode, isFeatureOn) &&
    isAccountantOnlyPath(location.pathname)) {
  history.replace('/');
}
```

Пункты меню для этого **уже помечены** `accountantOnly: true` — все шесть.
И в прежнем боковом меню была проверка, которая их прятала.

Но живое меню рисует **другой, новый компонент** (`ConnectedSidebar`).
Он собирает пункты сам и смотрит только на флаг модуля:

```ts
if (!node.feature || featureCan(node.feature)) acc.push(...)
```

Пометку `accountantOnly` он не знает. Проверку прав — тоже.

Счёт по меню: **86 пометок, из них новый сайдбар чтит 25**.

| Пометка | Сколько в меню | Учитывается |
|---|---|---|
| `feature` — модуль включён | 25 | да |
| `permission` — есть право | 55 | **нет** |
| `accountantOnly` — режим «Бухгалтер» | 6 | **нет** |

Последствие с `accountantOnly` проверено живьём: в демо-организации
(режим «Бизнес») все шесть пунктов на месте, и каждый уводит на главную.
На стенде в режиме «Бизнес» **девять организаций из двадцати**.

Последствие с правами видно в коде: прежнее меню проверяло право на
раздел, новое — нет; человеку покажут пункт, который ему закрыт.

Это знакомый класс: механизм есть, а новый экран о нём не знает.

### Линия 2. Шапки отчётов приходят по-английски

Отчёт «Дебиторка по срокам» рисует шапку так:

```
CUSTOMER NAME | CURRENT | 0 - 30 | 31 - 60 | 61 - AND OVER | TOTAL
```

Остальное в отчёте по-русски: «На 27.08.2026», «ООО «Ромашка»». Подписи
столбцов приходят с сервера, и там они вписаны руками:

```ts
return { label: 'Customer name', key: 'customer_name' };
```

Механизм перевода в этих же файлах есть и работает — баланс печатает
«НАЗВАНИЕ СТАТЬИ» через `this.i18n.t('balance_sheet.total')`.

Замер по отчётам: **переведённых подписей 47, вписанных по-английски —
52** в десяти файлах: «Item name», «Sold quantity», «Vendor name»,
«Average Price», «Quantity Purchased».

## 3. Фаза «Меню обещает то, чего не покажет» — срезы

1. **Л1 — меню не предлагает того, чего не покажет.** Новый сайдбар
   учитывает все пометки меню: флаг модуля, право на раздел и режим
   интерфейса. Сторож: у каждой пометки, объявленной в меню, есть
   проверка в том компоненте, который меню рисует.
2. **Л2 — шапки отчётов по-русски.** Пятьдесят две подписи переезжают в
   словарь сервера рядом с теми сорока семью, что уже переведены. Сторож:
   подпись столбца отчёта не вписывается в код латиницей.

Порядок: Л1 → Л2.
Каждый срез: красный тест → правка → полные прогоны → живая проба на
собранной витрине → PR с числами.
