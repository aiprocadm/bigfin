# ⑨a Парсеры банковских выписок: CSV и Excel — дизайн

Дата: 2026-07-31. Дорожная карта v5 §5 п. 6 («доводка частичных по запросу
dogfooding»), пункт ⑨a.

## 1. Что есть сейчас

`BankStatementImport` принимает **только** `1CClientBankExchange` (`.txt`):
`parse1CStatement` → `resolveDirection` (по номеру нашего счёта) →
`buildExternalId` (дедуп) → `CreateUncategorizedTransactionService`
(конвейер «Разбор» ⑨). Эндпоинт: `POST /cashflow-accounts/:id/import/1c`,
на фронте — один input с `accept=".txt"`.

Банки, которые не отдают формат 1С (а таких много: выгрузка «в Excel» из
интернет-банка — самый частый способ), не поддерживаются: выписку
приходится вбивать руками.

## 2. Цель и рамки

Принимать выписку **таблицей**: `.csv` и `.xlsx/.xls`, с автоматическим
распознаванием колонок по заголовку.

**В объёме:** разбор таблицы, распознавание колонок, извлечение операций,
предпросмотр перед импортом, импорт в тот же конвейер «Разбор», выбор файла
любого из трёх форматов на существующей странице.

**Вне объёма:** PDF (без библиотеки разбора PDF это нереализуемо честно —
в прямых зависимостях её нет, а добавлять пакеты нельзя); ручное
сопоставление колонок в UI (сейчас только автораспознавание + понятная
ошибка); шаблоны под конкретные банки.

## 3. Зависимости

`xlsx@^0.18.5` уже в прямых зависимостях `@bigfin/server` и используется в
модуле `Import` (`sheet_utils.ts`). Она читает и `.xlsx/.xls`, и `.csv`,
поэтому оба формата разбираются одним путём — новых пакетов не нужно.

Кодировка CSV: 1С и банки часто отдают windows-1251. Буфер декодируем
существующим `decodeStatementBuffer`, а в `xlsx` передаём уже строку
(`type: 'string'`), чтобы не зависеть от её угадывания кодировки.

## 4. Распознавание колонок

`utils/parseTableStatement.ts` — чистые функции.

Заголовок ищется в первых 20 строках: строка, где распознались хотя бы
**дата** и (**сумма** либо пара **приход/расход**). Всё выше — шапка
банка (реквизиты, период), она игнорируется.

Синонимы (регистр и пробелы не важны, сравнение по «содержит»):

| Поле | Синонимы |
|---|---|
| дата | `дата`, `дата операции`, `дата проводки`, `date` |
| сумма | `сумма`, `amount` |
| приход | `приход`, `поступление`, `кредит`, `credit`, `дебет счёта` |
| расход | `расход`, `списание`, `дебет`, `debit` |
| назначение | `назначение`, `основание`, `описание`, `purpose`, `description` |
| контрагент | `контрагент`, `плательщик`, `получатель`, `counterparty`, `payee` |
| ИНН | `инн`, `inn` |
| номер документа | `номер`, `док`, `№`, `number` |

Если распознать дату+сумму не удалось — доменная ошибка
`STATEMENT_COLUMNS_NOT_RECOGNIZED` с перечислением найденных заголовков,
чтобы пользователь понял, что не так.

**Знак операции:**
- две колонки (приход/расход) → знак по заполненной;
- одна колонка «сумма» → знак из самого числа; если все значения
  положительные и есть колонка с типом операции (`тип`, `вид операции`)
  со значением вида `списание`/`расход`/`debit` — минус по ней;
- иначе сумма без знака считается приходом, и это отражается в отчёте
  предупреждением (`amountSignAssumed`), чтобы пользователь заметил.

**Дата:** `ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`, `ДД/ММ/ГГГГ`, а также серийные числа
Excel (xlsx отдаёт даты числами) — распознаются все четыре.

**Сумма:** пробелы и неразрывные пробелы убираются, запятая → точка,
символ валюты отбрасывается.

## 5. Данные и дедупликация

Каждая строка → та же каноническая запись, что и у 1С-парсера
(`BankApiOperation`-подобная): `date`, `amount` (знаковая), `payee`,
`payeeInn`, `referenceNo`, `description`, `externalId`.

`externalId` = `table:<хэш>` где хэш — sha1 от
`дата|сумма|номер|назначение` (номер и назначение часто пустые, но вместе с
датой и суммой дают устойчивый ключ). Дедупликация — как в 1С: по
`(accountId, externalId)`.

## 6. Сервисы и API

- `ParseTableStatementService` не нужен: разбор — чистая функция
  `parseTableStatement(text | buffer, fileName)`.
- `ImportTableStatementService.preview(accountId, buffer, fileName)` →
  `{ rows: ParsedRow[], toImport, duplicates, warnings }` (ничего не пишет,
  первые 20 строк отдаются для показа).
- `ImportTableStatementService.import(accountId, currencyCode, buffer, fileName)`
  → `{ imported, skipped }`.

Эндпоинты рядом с существующим (тот же контроллер, флаг
`bank_statement_import`, право `manage all`, лимит 10 МБ):

- `POST /cashflow-accounts/:accountId/import/table/preview`
- `POST /cashflow-accounts/:accountId/import/table`

Фильтр файлов: `.csv`, `.xlsx`, `.xls`.

## 7. Фронт

На существующей странице импорта — второй блок «Выписка таблицей
(CSV/Excel)»: выбор файла → «Проверить» (показывает распознанные колонки,
число операций, дубликаты и предупреждения, первые строки таблицей) →
«Импортировать». Строки через `intl.get`, ключи `bank_import.table.*`
парно en/ru.

## 8. Тестирование

- Распознавание колонок: русские и английские заголовки, шапка банка перед
  заголовком, две колонки прихода/расхода, одна знаковая колонка,
  нераспознанные колонки → доменная ошибка.
- Разбор значений: все четыре формата дат (включая серийные числа Excel),
  суммы с пробелами/запятой/валютой, пустые строки пропускаются.
- Дедупликация: повторный импорт того же файла ничего не добавляет.
- Живая проверка: сгенерировать `.csv` и `.xlsx` (через ту же `xlsx`),
  прогнать предпросмотр и импорт на стенде, проверить операции в «Разборе».

## 9. Порядок работ

1. Парсер таблицы (распознавание колонок + значения) с тестами.
2. Сервис предпросмотра/импорта + эндпоинты.
3. Фронт: блок на странице импорта, хуки, i18n.
4. Живой прогон на CSV и XLSX.
