## Что было на старте (шаг 3.1)

- Экран операций — `containers/CashFlow/AccountTransactions/*`, привязан к
  одному счёту: адрес `/cashflow-accounts/:id/transactions`. Адреса
  «все операции» (`/cashflow-accounts/transactions`) в таблице маршрутов нет.
- Серверная ручка `GET /banking/transactions` существовала, но **требовала
  счёт**: в `GetBankTransactionsQueryDto` поле `accountId` было помечено
  `@IsNotEmpty()`, а запрос всегда ставил `where account_id = …`.
- У модели операции уже были готовые отборы (`filterAccounts`,
  `filterDateRange`, `filterTransactionTypes`, `filterContactIds`) — но список
  операций ими не пользовался.

## Что сделано в шаге 3.2 (сервер)

1. **Счёт стал необязательным.** Пусто — операции по всем счетам организации.
   Со счётом поведение прежнее, включая входящий и бегущий остаток.
2. **Добавлены отборы** из п. 3.1 ТЗ: период (`fromDate`/`toDate`),
   направление денег (`flow`: `in`/`out`), контрагент, сумма от–до, поиск по
   номеру, номеру-ссылке и примечанию.
3. **Входящий остаток не считается без счёта** — по разным счетам накопительный
   итог не имеет смысла; отдаётся ноль, запрос в базу не идёт.
4. **Сторож** `allAccountsTransactions.spec.ts` — 6 проверок, проверен
   мутацией (возврат жёсткого `where account_id` роняет 4 из 6).

Попутно починена красная проверка типов сервера: тест уборки демо
(`OneClickDemoData.spec.ts`) передавал конструктору 7 доводов вместо 8. Это
было на `develop` до начала работы и блокировало обязательный зелёный прогон.

**Прогон:** сервер 2310 тестов / 345 наборов зелено; `tsc` сервера и витрины
чисты; словари 4238 / 4238.

**Как проверить:** `GET /banking/transactions?page=1&pageSize=50` без
`accountId` отдаёт операции по всем счетам; с `accountId=<id>` — как раньше.
**Как откатить:** `git revert` коммита шага 3.2.

## Что сделано в шаге 3.3 (витрина)

**Новый экран** `/cashflow-accounts/transactions` — список операций по всем
счетам. Адрес из двух сегментов, со старым `/cashflow-accounts/:id/transactions`
(три сегмента) не пересекается; ни один прежний адрес не тронут.

Собран на новой дизайн-системе, как требует ТЗ: `PageHeader`, `ListToolbar`,
`DataTable`, `DatePicker`, `Select`, `EmptyState` из `components/ui/`.

- **Период** — по умолчанию текущий месяц, две даты в шапке.
- **Отборы**: счёт (все счета / конкретный), направление денег (все /
  поступления / списания), поиск по назначению и номеру.
- **Отборы в адресной строке** — ссылку можно переслать, вид сохраняется
  (часть приёмки этапа 3). Мусор из чужой ссылки отборами не становится.
- **Колонки**: дата, контрагент, назначение (обрезается, полное — в подсказке),
  тип, счёт, сумма. Приход зелёным, расход красным — по токенам системы.
- **Подгрузка** по кнопке «Показать ещё» + счётчик «показано N из M».
- **Пункт меню** «Операции» — первым в группе «Банк». Полная перестройка меню
  остаётся этапом 1; здесь только вход на новый экран.

Сервер в этом же шаге дополнен: в строке появились счёт, контрагент и
назначение платежа — без них список по всем счетам не читается.

Попутно: `useCashflowAccounts` требовал два обязательных довода, хотя список
счетов часто нужен «как есть» — сделаны необязательными (класс карт v87–v88).

**Прогон:** витрина 988 тестов / 132 файла, сервер 2310 / 345, типы обоих
пакетов чисты, словари 4250 / 4250 (+12 ключей), `vite build` 2 м 58 с.

**Как проверить:** «Банк → Операции» в меню, либо адрес
`/cashflow-accounts/transactions`. Смена периода и отборов меняет адрес.
**Как откатить:** `git revert` коммита шага 3.3.

## Что сделано в шаге 3.4 (ждут разноски)

Полоса состояния из п. 3.1 ТЗ: «N операций ждут разноски» и вход в разноску
одним нажатием.

**Сервер.** Операции, ждущие разноски, отдавались только по одному счёту
(`GET /banking/uncategorized/accounts/:accountId`) — общее число нельзя было
узнать, не обойдя все счета. Заведена ручка `GET /banking/uncategorized`: счёт
стал необязательным, остальные условия (не разнесена, не исключена, не в
ожидании) сохранены. Сторож `allAccountsUncategorized.spec.ts` — 3 проверки.

**Витрина.** На экране «Операции»:

- полоса с числом ждущих и кнопкой «Показать» — видна только когда есть что
  разносить;
- режим «Ждут разноски» со своими колонками: дата, контрагент, назначение,
  **подсказка от правила** («Похоже на „Аренда офиса“» — сервер уже отдаёт её
  в `assigned_account_name`), счёт, сумма;
- режим хранится в адресе (`?status=uncategorized`) и на сервер списка
  проведённых операций не уходит;
- «Показать ещё» и счётчик работают в обоих режимах.

**Прогон:** сервер 2313 / 346, витрина 991 / 132, типы чисты, словари
4259 / 4259 (+9 ключей), `vite build` 2 м 49 с.

**Замечание о прогоне:** в первом полном прогоне сервера упал чужой тест
двухфакторной проверки (`TwoFactor.services.spec.ts`) — таймаут 5 секунд под
общей нагрузкой. В одиночку и при повторном полном прогоне он зелёный: тест
«мигающий», к правкам этого шага отношения не имеет.

**Как проверить:** «Банк → Операции»; если есть неразнесённые операции —
появится полоса, кнопка «Показать» переключает список и меняет адрес.
**Как откатить:** `git revert` коммита шага 3.4.

## Что сделано в шаге 3.5 (разнос одним движением)

В режиме «Ждут разноски» колонка «Статья» стала рабочей: человек выбирает
статью в выпадающем списке с поиском — операция разносится сразу, без единого
окна. Это главное требование приёмки этапа.

- **Сторона операции определяет выбор.** Поступление ждёт статью из доходов и
  уходит типом «прочий доход», списание — из расходов и «прочий расход».
  Перепутать нельзя: список статей отбирается по стороне строки.
- **Подсказка от правила — в один клик.** Если правило разноски сработало,
  рядом стоит кнопка «Применить „Аренда“».
- **Назначение платежа и контрагент переносятся** в созданную операцию: иначе
  строка теряет единственное, по чему её узнают в отчётах.
- **Отказ сервера показывается причиной**, а не общими словами: разнос идёт
  подряд, и видно, какая именно строка не прошла.
- Полный набор типов (взнос собственника, перевод между счетами) остаётся в
  подробной форме — в строке только два обычных случая.

Вся логика вынесена в `categorizeInline.ts` без React и покрыта тестами
(7 проверок), включая защиту от подмены стороны и от пустых полей в запросе.

**Прогон:** витрина 1001 тест / 133 файла, сервер 2313 / 346, типы обоих
пакетов чисты, словари 4263 / 4263 (+4 ключа), `vite build` 2 м 23 с.

**Как проверить:** «Банк → Операции» → «Показать» у полосы ждущих разноски →
выбрать статью в строке. Операция уходит из списка, счётчик уменьшается.
**Как откатить:** `git revert` коммита шага 3.5.
