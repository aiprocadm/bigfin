## Архитектура (двухуровневая)

```
App.tsx
  └─ <Route path='/auth' children={<AuthenticationPage />} />
       └─ AuthenticationPage.tsx (гард: EnsureAuthNotAuthenticated)
            └─ Authentication.tsx (логотип + CSSTransition оболочка)
                 └─ <Switch> по authenticationRoutes
                      └─ конкретный экран (Login / Register / SendResetPassword / ...)
```

**Гарды как контракт:**
- `/auth/*` обёрнут `EnsureAuthNotAuthenticated` → если уже залогинен, редирект на `/`.
- Остальные роуты `/` обёрнуты `EnsureAuthenticated` → если НЕ залогинен, редирект на `/auth/login`.
- **Это значит:** в новых onSubmit-хендлерах НЕ нужно вызывать `history.push('/dashboard')` после успешного login. Гард перерендерит дерево автоматически после смены auth-state.

## Роуты (единая точка подмены)

Файл: `packages/webapp/src/routes/authentication.tsx`

```ts
export default [
  { path: '/auth/login',                            component: lazy(...Login) },
  { path: '/auth/send_reset_password',              component: lazy(...SendResetPassword) },  // ⚠️ underscore
  { path: '/auth/reset_password/:token',            component: lazy(...ResetPassword) },
  { path: '/auth/invite/:token/accept',             component: lazy(...InviteAccept) },
  { path: '/auth/register/email_confirmation',      component: lazy(...EmailConfirmation) },
  { path: '/auth/register',                         component: lazy(...Register) },
];
```

**⚠️ Несостыковка URL:** в Storybook `Link.stories.tsx` уже используется `/auth/forgot-password` (kebab-case). Старый роут — `/auth/send_reset_password` (underscore). Решение для Phase 2:

- Минимальный вариант: оставить старый underscore-URL, в новых компонентах ссылаться на `/auth/send_reset_password`. Это не ломает старые письма со ссылками.
- Идеальный вариант: добавить новый kebab-роут как primary, старый оставить как редирект. Перенести позже отдельным под-проектом (D-Phase-3).

Решение по умолчанию для Phase 2 — **минимальный вариант**, чтобы не плодить риски миграции URL.

## API-хуки для submit (`hooks/query/authentication.tsx`)

| Хук | HTTP | Поля запроса | onSuccess делает |
|---|---|---|---|
| `useAuthLogin` | POST `auth/signin` | `{email, password}` | setCookie(token, user_id, organization_id) + Redux: setAuthToken/setOrganizationId/setUserId. **Гард `EnsureAuthenticated` сам перерендерит и пустит на `/`.** |
| `useAuthRegister` | POST `auth/signup` | `{first_name, last_name, email, password}` | Ничего автоматически. **Старый Register.tsx сразу зовёт `useAuthLogin` после signup** — это поведение сохранить. |
| `useAuthSendResetPassword` | POST `auth/send_reset_password` | `{email}` | Ничего. Старый код показывает toast «check your email» и `history.push('/auth/login')`. Сохранить. |
| `useAuthResetPassword` | POST `auth/reset/:token` | `{password}` | D-Phase-3, не Phase 2. |

## Поля старых форм vs новых

| Что | Старое имя | Новое имя в Phase 2 |
|---|---|---|
| Email в login | `crediential` (опечатка) | `email` |
| Email в send-reset | `crediential` (опечатка) | `email` |
| Чекбокс «запомнить» | `keepLoggedIn` | `keepLoggedIn` (оставить — API его игнорирует, но UI ожидаем) |
| Имя | `first_name` | `firstName` (camelCase в форме, мап в snake_case на отправке) |
| Фамилия | `last_name` | `lastName` (то же) |
| Пароль | `password` | `password` |

**Замечание:** API ожидает snake_case (`first_name`, `last_name`). Маппинг сделать в onSubmit:
```ts
authRegisterMutate({
  first_name: values.firstName,
  last_name: values.lastName,
  email: values.email,
  password: values.password,
});
```

## Поведение редиректов

| Событие | Куда | Кто делает |
|---|---|---|
| Успешный login | `/` (затем дашборд через guard) | Гард `EnsureAuthenticated` при следующем рендере |
| Успешный register | `/auth/register/verify` (через email-verify guard) | После `authRegisterMutate → authLoginMutate` гарды перенаправят |
| Успешный send-reset | `/auth/login` + toast | Ручной `history.push` в onSubmit |
| Ошибка login | toast через `transformLoginErrorsToToasts` | Старый код — в новом будем использовать новый `Toaster` из `components/ui/sonner` |
| Ошибка register | form-errors через `transformRegisterErrorsToForm` + toast | То же — заменим на zod-валидацию + Toaster |

## Что нужно для Task 2.2 (zod-схемы)

Три схемы:
- `LoginSchema` — `email: z.string().email(...)`, `password: z.string().min(8, ...)`, `keepLoggedIn: z.boolean().optional()`
- `RegisterSchema` — `firstName: z.string().min(1)`, `lastName: z.string().min(1)`, `email: z.string().email(...)`, `password: z.string().min(8)`
- `ForgotPasswordSchema` — только `email: z.string().email(...)`

Тексты ошибок — на русском (целевая аудитория Bigfin). Брать ключи из `intl` нельзя пока — формы пилотные, локализацию подключим в D-Phase-3. Хардкод RU-сообщения с TODO-комментарием.
