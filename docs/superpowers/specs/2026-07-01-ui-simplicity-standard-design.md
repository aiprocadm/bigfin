# Стандарт «Простота Bigfin» — правила чистого UI

**Дата:** 2026-07-01
**Тип документа:** Дизайн-стандарт (линза простоты поверх дизайн-системы D)
**Статус:** Draft → ожидает review основателя
**Связь с roadmap:** Не отдельный под-проект. Это **правила**, которые применяются при
миграции каждой страницы в рамках [D-редизайна](2026-05-25-redesign-design.md).

---

## 1. Зачем этот документ

Запрос основателя: «современный, удобный для пользователя дизайн, без перегруза на
страницах — просто и удобно, все страницы».

Ключевой вывод после сборки макетов: у Bigfin **уже есть** дизайн-система (токены в
`packages/webapp/src/styles/tokens.css`, shadcn-примитивы, светлая тема Bold Fintech).
«Перегруженность» живёт не в новой системе, а в ~900 старых экранах на Blueprint.js.

Поэтому это **не новая система**, а **линза простоты**: короткий свод правил, по которому
любая страница при миграции приобретает единый чистый вид. Направление не меняется —
уточняется дисциплина применения.

**Как это сочетается со стратегией:** способ внедрения прежний — Strangler Fig,
**один экран = один PR**, откат = `git revert`. Единоразовой переделки всех ~90 страниц
не делаем (это анти-паттерн, зафиксированный в спеке D-редизайна).

---

## 2. Шесть правил простоты

1. **Один акцент.** Жёлтый `#FFD300` (`--c-accent`) — только логотип, выделения и редкий
   статус-сигнал. Кнопки — чернильные `#1A1D29` (`--c-action`). Так записано в токенах;
   правило лишь закрепляет дисциплину. Глазу негде «спотыкаться».
2. **Воздух вместо линий.** Разделители — волосяные `--c-border`; между блоками —
   пространство. Ни тяжёлых рамок, ни декоративных теней.
3. **Один главный акцент действия на экран.** Ровно одна primary-кнопка (ink); остальные —
   ghost или secondary. Пользователь всегда видит, что делать.
4. **Деньги читаются как деньги.** `font-variant-numeric: tabular-nums` (уже включён в
   `.bigfin-ui`), приход — `--c-success`, расход — спокойным тёмным. Красный (`--c-danger`)
   бережём для просрочки/ошибок, а не для любого минуса.
5. **Заголовки по-человечески.** «Сколько бизнес заработал после всех расходов» вместо
   «P&L Statement». Аудитория — предприниматель без бухгалтерского образования.
6. **Пусто — это приглашение.** Пустое состояние = заголовок + одна строка объяснения +
   одна кнопка-действие. Не «Здесь пока ничего нет».

---

## 3. Главный принцип: просто ≠ мало данных

Макет ОПиУ показывает ~50 чисел и остаётся спокойным. Простота достигается **иерархией,
воздухом, сдержанным цветом и возможностью свернуть детали** — не выбрасыванием
информации. Плотный экран может быть простым; редкий — перегруженным. Решает организация,
а не количество.

---

## 4. Токены — не изобретать

Берём из `packages/webapp/src/styles/tokens.css`. Не вводим новые цвета/шрифты.

| Роль | Токен | Значение |
|---|---|---|
| Фон приложения | `--c-background` | `#F4F5F7` |
| Карточки, панели | `--c-surface` | `#FFFFFF` |
| Границы, разделители | `--c-border` | `#E4E7EC` |
| Основной текст | `--c-text-primary` | `#1A1D29` |
| Вторичный текст | `--c-text-secondary` | `#5A6478` |
| Подписи, плейсхолдеры | `--c-text-muted` | `#98A2B3` |
| Кнопки, ключевые действия | `--c-action` | `#1A1D29` (чернильный) |
| Фирменный акцент | `--c-accent` | `#FFD300` (жёлтый) |
| Доход, успех | `--c-success` | `#1F9D57` |
| Расход-ошибка, просрочка | `--c-danger` | `#E5484D` |
| Скругление | `--radius` | `8px` (карточки — `12px`) |
| Шрифт | `--font-sans` | Inter Variable |

Светлая тема — основная; тёмная (`.dark`) — опция, не приоритет.

## 5. Паттерны по архетипам (проверено на макетах)

**Каркас (все страницы).** Сайдбар белый, границы волосяные; топбар минимальный
(поиск + колокол + аватар). Активный пункт меню — тёмный текст + жёлтая точка-индикатор.

**Дашборд.** 2–4 метрика-карточки, один график, список последних операций. Не «стена
виджетов».

**Список / таблица.** Тулбар = поиск + один фильтр + одна primary-кнопка. Строки через
волосяной разделитель (не карточки-плитки), статусы — пилюли, пагинация простая.

**Форма.** Поля сгруппированы в карточки по смыслу; ключевое поле — крупное; сетка в
2 колонки, где уместно; внизу одна primary + ghost.

**Отчёт.** Иерархия строк (группа → подстатья → итог), сворачиваемые группы, плашки
итогов, `tabular-nums`, минусы — спокойным серым.

**Мобильный.** Навигация внизу (под большой палец), крупная центральная кнопка «＋» для
ежедневного действия, одна колонка, крупные зоны касания, детали — за шевроном.

**Настройки.** Горизонтальные вкладки вместо второго сайдбара; карточки-группы полей;
закреплённая внизу панель сохранения с единственной primary-кнопкой.

---

## 6. Что НЕ меняем

- Токены, палитру, шрифт (заданы в `tokens.css` / `globals.css`).
- Стратегию миграции: Strangler Fig, один экран = один PR, откат = `git revert`.
- Бизнес-логику, сервер, схему БД.
- **Не** переписываем легаси-страницы «на ходу» без явного запроса.

## 7. Зафиксированные правки к коду (вносим по мере миграции)

- **`Sidebar.tsx` — активный пункт.** Сейчас `bg-accent/10 text-accent` — жёлтый текст на
  бледно-жёлтом (низкий контраст). Заменить на тёмный текст + жёлтая точка-индикатор.
  Внести при первой странице, которая затрагивает сайдбар.

## Приложение: чек-лист простоты (для каждого PR)

- [ ] Ровно одна primary-кнопка на экран?
- [ ] Жёлтый только акцент/лого/сигнал — не фон кнопок?
- [ ] Деньги через `tabular-nums`, приход/расход по правилу цвета?
- [ ] Разделители волосяные, без тяжёлых теней и рамок?
- [ ] Заголовок сформулирован по-человечески?
- [ ] Пустое / загрузочное / ошибочное состояния оформлены?
- [ ] Проверено на узком (мобильном) экране?
- [ ] Все видимые строки — через `intl.get(...)` / `<T id=.../>` (без хардкода)?
