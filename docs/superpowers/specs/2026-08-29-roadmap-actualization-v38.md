# Bigfin — Дорожная карта v38 «Продукт по своей же инструкции» — 2026-08-29

Карта v37 закрыта целиком (#362): напечатанное «1000,50» больше не
превращается в 100050, дробь печатается знаком организации. Открытых
вопросов у владельца нет. GitHub Actions по-прежнему выключены до
сентября, проверки гоняются вручную и приводятся числами в PR.

---

## 1. Что дала разведка

Разведка началась с поиска в шапке, а закончилась в неожиданном месте.

Пробуя напечатать счёт на своём опытном сервере, я получил **500**. Стенд
при этом печатает нормально. Первым делом проверил, не врёт ли измеритель
(урок карты v35): тот же счёт с настоящего стенда — `200`, PDF на 37 КБ.
Значит, дело не в продукте? Оказалось — именно в продукте.

### Находка 1 (главная). Настройка, прочитанная слишком рано

Сервер **не читает `.env` сам** — его читает `ConfigModule` уже во время
запуска приложения. А адрес службы печати запоминается раньше — в момент
загрузки модуля:

```ts
public static readonly GOTENBERG_ENDPOINT = process.env.GOTENBERG_URL || '';
```

К этой строке `.env` ещё не прочитан. Адрес получается пустым, и печать
падает с `TypeError: Invalid URL`.

Стенд работает только потому, что его настройки подставляет systemd
(`EnvironmentFile=`) — то есть ДО старта процесса. Тот же код, тот же
`.env`, разница только во времени:

| Как запущен сервер | Печать счёта |
|---|---|
| приложение читает `.env` само (как велит инструкция) | **500** |
| настройки подставлены заранее (как на стенде) | **200**, PDF 47 КБ |

Замер по четырём формам — счёт, счёт на оплату, акт, УПД: **4 из 4 → 500**
на первом способе и **4 из 4 → 200** на втором. Через службу печати
проходят **38 файлов**: все российские печатные формы (счёт на оплату,
акт, УПД, ТОРГ-12, счёт-фактура, акт сверки), счета, сметы, чеки и
выгрузки в PDF.

Инструкция (`CONTRIBUTING.md`) ведёт ровно по сломанному пути:
`cp .env.example .env` → `pnpm install` → `pnpm dev`. Переменная
`GOTENBERG_URL` в примере настроек есть — человек её ставит, а она не
действует.

Тем же способом читаются ещё две настройки — потолки строк выгрузки и
отчёта (`EXPORT_ROWS_LIMIT`, `REPORT_ROWS_LIMIT`). Они не падают, а молча
остаются со значением по умолчанию. В коде рядом написано: «Значение можно
переопределить переменной окружения» — из `.env` нельзя.

### Находка 2. «Docker (рекомендуется)» не поднимает продукт

README:

> ### Docker (рекомендуется)
> `docker compose up -d`
> После старта откройте http://localhost:80

В `docker-compose.yml` **три службы**: `mariadb`, `redis`, `gotenberg`.
Ни сервера, ни витрины там нет — на `localhost:80` открывать нечего.
Файл сам себя объясняет в первой строке («development version… avoid
using in production»), то есть он и не должен поднимать продукт. Обещание
даёт инструкция.

### Находка 3. Инструкция называет не ту базу данных

README, дважды: «Требования: Node.js 18.16.1, pnpm, **PostgreSQL**, Redis»
и «Бэкенд: … **PostgreSQL**, Redis, Knex». Продукт работает на
**MySQL/MariaDB**: в `docker-compose.yml` образ mariadb, драйвер `mysql`,
в `.env.example` переменные MySQL. Человек, идущий по инструкции, ставит
не ту базу.

## 2. Фаза «Продукт по своей же инструкции» — срезы

1. **Н1 — настройка действует, когда её прочитали.** Три места перестают
   читать окружение на загрузке модуля. Сторож: настройки не читаются в
   момент загрузки — только в момент обращения.
2. **Н2 — инструкция обещает ровно то, что делает.** README про Docker и
   про базу данных; недостающие настройки — в пример. Сторож сверяет
   инструкцию с продуктом.
3. **Н3 — сбой печати не выглядит успехом.** Найдено живой пробой первого
   среза: когда служба печати отвечает ошибкой, продукт отдаёт код 200 и
   файл с текстом ошибки вместо документа.

Порядок: Н1 → Н2 → Н3.
Каждый срез: красный тест → правка → полные прогоны → живая проба → PR с
числами.

---

## 3. Что сделано

### Н1 — настройка действует, когда её прочитали

Три места перестали спрашивать окружение на загрузке модуля:

- адрес службы печати и адрес шаблонов (`Chromiumly`) — теперь геттеры;
- потолок строк выгрузки (`exportRowsLimit()`) и потолок строк отчёта
  (`reportRowsLimit()`) — теперь функции; звавшие их места (двадцать с
  лишним файлов) перешли на вызов.

Сторож `settingsReadOnLoadGuard`: `process.env` спрашивают внутри функции,
метода или геттера — то есть тогда, когда `.env` уже прочитан. Проверен на
исходном грехе: возвращаю полю прежний вид — сторож краснеет и называет
файл и строку.

**Попутная находка.** У продукта ЕСТЬ описание этой настройки —
`common/config/gotenberg.ts` (`registerAs('gotenberg', …)`), и им не
пользуется никто: библиотека печати читает окружение мимо. Таких
описанных, но никем не читаемых пространств настроек три: `gotenberg`,
`lemonsqueezy`, `openExchange` — все три модуля читают те же переменные
напрямую. Ничего не сломано, поэтому не трогал; записано как долг.

### Н2 — инструкция обещает ровно то, что делает

README: раздел «Docker (рекомендуется) → откройте localhost:80» заменён
честным описанием — `docker-compose.yml` поднимает окружение (MariaDB,
Redis, служба печати), продукт запускается отдельно, витрина открывается
на `localhost:4000`, сервер на `localhost:3000` (порты сверены с
`packages/webapp/package.json` и `main.ts`). База данных названа своим
именем — MySQL/MariaDB вместо PostgreSQL, в двух местах.

`.env.example` пополнился двумя потолками объёма, которых там не было.

Сторож `readmeMatchesProduct`: README не называет базу, которой нет в
`docker-compose.yml`, и не зовёт открывать адрес, на котором никого нет.
Проверен на исходном грехе.

### Н3 — сбой печати не выглядит успехом

Живая проба первого среза вскрыла вторую половину задачи. Ответ службы
печати не проверялся вовсе:

```ts
const response = await new Axios({…}).post(endpoint, data);
return response.data;          // статус никто не смотрел
} catch (error) { console.error(error); }   // ошибка проглатывалась
```

Живьём: служба печати ответила «404: Not Found» — продукт отдал человеку
**код 200** и файл, внутри которого лежал этот текст вместо PDF. Такой
«счёт» не открывается ни одной программой, и понять почему неоткуда.
Вторая ветка: служба недоступна — «Internal server error» без причины.

Теперь ответ проверяется, а отказ объясняет себя: **503** и текст «Не
удалось напечатать документ: служба печати ответила ошибкой …». Пустой
ответ — тоже отказ, а не пустой файл.

### Живая проба

Сервер собран из рабочей копии и запущен **ровно по инструкции**: `.env`
рядом, ничего снаружи не подставлено (порт 3035, служба стенда не
тронута).

| Что проверял | Было | Стало |
|---|---|---|
| счёт в PDF | 500 | **200, PDF 47 209 байт** |
| УПД | 500 | **200, PDF 37 971 байт** |
| служба печати отвечает ошибкой | 200 + текст ошибки вместо PDF | **503 с объяснением** |
| служба печати недоступна | 500 без причины | **503 с объяснением** |
