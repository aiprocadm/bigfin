# Полная русификация Bigfin — дизайн

**Дата:** 2026-06-11
**Статус:** одобрено основателем (brainstorming-сессия)
**Скоуп:** первый из двух больших проектов («сначала русский, потом дизайн»). Редизайн UI — отдельный проект со своей спекой.

---

## Цель

Пользователь Bigfin (российский предприниматель без бухгалтерского образования) не встречает ни одного английского слова на всём пути: регистрация → настройка организации → повседневная работа → письма и документы его контрагентам → сообщения об ошибках.

## Ключевые решения

| Вопрос | Решение |
|---|---|
| Язык по умолчанию | **Русский** (интерфейс, новые организации) |
| Английский | Остаётся как опция в настройках (страховка на будущее) |
| Арабский | Убирается из списка выбора языка; файлы переводов **не удаляются** |
| Язык писем и PDF | **Язык организации** (настройка на сервере), не язык браузера |
| Язык интерфейса | Личный выбор пользователя (браузер), независим от языка документов |

## Контекст: что показал аудит кодовой базы

- **Веб-словарь полный**: 2905 ключей en = 2905 ru, парность 100% (`lang-check.js`).
- **Сервер почти готов**: 32 файла русских переводов в `packages/server/src/i18n/ru/` (~614 строк из 617 в en).
- **Блокер**: `ACCEPTED_LOCALES = ['en', 'ar']` в `packages/server/src/modules/Organization/Organization.constants.ts` — сервер отклоняет `language: 'ru'` для организации, поэтому готовые серверные переводы не используются.
- **Дефолтная локаль фронта — `en`** (`AppIntlLoader.tsx`); выбор языка живёт только в localStorage браузера.
- **~60–80 файлов веба** содержат английский, зашитый мимо словаря (placeholder/title/aria-label/toast; ~310 вхождений + явные тексты вроде `GlobalErrors.tsx:82`). Горячие точки: биллинг, банк, портал оплаты, мастер настройки, импорт/экспорт.
- **Письма (8 шаблонов в `shared/email-components`) и PDF (9 форм в `shared/pdf-templates`) без i18n**: все лейблы передаются props'ами, сервер заполняет их английскими строками; в `shared/pdf-templates/src/components/_constants.ts` зашиты английские заготовки.

## Архитектура решения

Подход «Фундамент → зоны»: один маленький этап с максимальным эффектом, затем четыре зоны строго по очереди. Каждый этап — отдельная ветка, проверяемая и откатываемая независимо.

### Этап 0 — Фундамент

1. `ACCEPTED_LOCALES` → `['en', 'ru', 'ar']` (одна строка, снимает блок с серверных переводов).
2. Дефолтная локаль фронта `en` → `ru` в `AppIntlLoader.tsx`. Сохранённый выбор пользователя уважается.
3. Новые организации создаются с языком `ru` по умолчанию (мастер настройки).
4. Из пикера языков убирается арабский: остаются «Русский» и «English». Файлы `ar/` остаются в репо.
5. Существующие организации автоматически не трогаем: после этапа 0 язык уже созданной организации переключается на русский вручную в настройках (для организации основателя — сделать и проверить в рамках приёмки этапа).

### Этап 1 — Веб-интерфейс (захардкоженный английский)

- Механика: английская строка → парный ключ в `lang/{en,ru}/index.json` → `intl.get('key')`.
- Порциями по разделам (биллинг, банк, портал оплаты, мастер настройки, импорт/экспорт, …): одна порция = одно изменение; после каждой — `lang-check.js` + `pnpm typecheck`.
- **Сканер-сторож**: новый скрипт `packages/webapp/scripts/hardcoded-text-check.js` — ищет подозрительные английские строки в JSX (текст-узлы, `placeholder=`, `title=`, `label=`, `aria-label=`, toast/alert). Белый список: брендинговые исключения («Email», «PRO», «ID», «IP», «Paypal», форматные спецификаторы дат), имена компонентов, технические значения. Критерий готовности этапа: ноль находок вне белого списка.
- Новые ключи в `ar/` не добавляются (локаль скрыта, fallback на en допустим).

### Этап 2 — Серверные ошибки

1. Выровнять парность серверных переводов en↔ru (617 vs ~614 строк — найти и перевести недостающие).
2. Схема показа ошибок: **фронт переводит по коду ошибки** (`ServiceError.errorType` → ключ словаря). Код — стабильный контракт, текст — оформление; один сервер обслуживает пользователей с разными языками интерфейса. Места, где английский `message` с сервера показывается «как есть» (включая зашитый текст о подписке в `GlobalErrors.tsx:82`), переводятся на эту схему.
3. Тексты, которые генерирует сам сервер (понадобится для этапов 3–4), берутся через nestjs-i18n **на языке организации** из `tenants_metadata` (system-схема), а не из заголовков запроса.

### Этап 3 — Письма клиентам

- 8 шаблонов в `shared/email-components` остаются props-based («формы с окошками») — это правильная архитектура, её не меняем.
- Меняется заполняющая сторона: код отправки на сервере берёт лейблы и тексты-заготовки из серверных файлов переводов на языке организации. Новые ключи — парно en+ru.

### Этап 4 — PDF-документы

- **Первым делом — спайк по кириллице**: короткий эксперимент, что PDF-движок рендерит русский текст без «квадратиков». Это главный технический риск проекта; проверяем до основной работы. Если шрифты не умеют кириллицу — подключаем шрифт с её поддержкой, и только потом продолжаем.
- Далее по схеме этапа 3: лейблы 9 печатных форм заполняются сервером на языке организации.
- Перевод зашитых заготовок в `shared/pdf-templates/src/components/_constants.ts` (условия оплаты, примеры позиций, текст благодарности) — через тот же механизм языка организации; предпросмотры шаблонов в вебе используют ключи веб-словаря.

## Критерии готовности (проверка на локальном стеке, со скриншотами)

1. Новая организация: регистрация → мастер → главный экран — без единого английского слова.
2. Сканер-сторож: ноль находок вне белого списка; `lang-check.js` зелёный.
3. Тестовый счёт → PDF на русском, кириллица читаема.
4. Тестовое письмо клиенту — полностью на русском.
5. Спровоцированная ошибка (например, удаление системного счёта) — по-русски.

## Риски

| Риск | Митигация |
|---|---|
| Кириллица в PDF-шрифтах | Спайк в начале этапа 4, до основной работы |
| Английский «затекает» обратно с новыми фичами | Сканер-сторож + существующий PostToolUse-хук lang-check |
| Сканер даёт ложные срабатывания | Белый список в конфиге сканера, пополняется осознанно |
| Большой объём этапа 1 (60–80 файлов) | Порции по разделам, после каждой — проверка и пауза |

## Вне скоупа

- Редизайн UI (второй проект, отдельная brainstorming-сессия после завершения русификации).
- Удаление файлов локалей `ar/es/sv` — ничего не удаляем без отдельного решения.
- Перевод технической документации репозитория.
