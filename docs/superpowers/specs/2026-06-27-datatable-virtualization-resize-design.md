# Виртуализация строк и ресайз колонок в примитиве `data-table.tsx` (D-redesign, слайс 3 — энейблер) — дизайн

**Дата:** 2026-06-27
**Статус:** утверждён основателем (брейншторм)
**Контекст роадмапа:** D-redesign, миграция экрана «Движение денег» (CashFlow). Слайс 1 (форма категоризации) и слайс 2 (таблица «Все транзакции») влиты. Этот слайс — технический энейблер: расширяет общий примитив `components/ui/data-table.tsx`, чтобы следующие слайсы могли перенести 4 таблицы вкладки «без категории» (uncategorized / recognized / excluded / pending), которые в легаси опираются на виртуализацию (`TableVirtualizedListRows`) и запоминание ширин колонок (`useMemorizedColumnsWidths`).

---

## Цель

Добавить в примитив `data-table.tsx` две **опциональные, по умолчанию выключенные** способности:
1. **Виртуализация строк** — рендерить только видимые строки длинного списка (мгновенная прокрутка тысяч неразобранных операций).
2. **Ресайз колонок** — перетаскиваемая граница в шапке; ширины запоминаются на стороне вызова.

Поскольку обе способности опциональны и выключены по умолчанию, таблица «Все транзакции» из слайса 2 не затрагивается — нулевой риск регресса.

---

## Выбранный подход (A): самописное окно фиксированной высоты, без новых зависимостей

Отвергнутые альтернативы:
- **B — переиспользовать легаси `react-virtualized`** (уже в проекте): не дружит с семантическим `<table>`, сломал бы чистую вёрстку нового примитива.
- **C — добавить `@tanstack/react-virtual`**: новая зависимость; `pnpm install` болезненный на Windows (bcrypt). Требует явного решения, отложено.

Подход A: ноль новых зависимостей, таблица остаётся чистым `<table>`, ключевая логика — чистые функции, покрываемые тестами.

## Виртуализация — интерфейс и поток данных

**Новые пропсы (`DataTableProps`):**

| Проп | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `virtualized` | `boolean` | `false` | Включает виртуализацию строк |
| `rowHeight` | `number` | `40` | Фиксированная высота строки в px (легаси: 34 «small» / 40 «normal») |
| `overscan` | `number` | `8` | Сколько строк рендерить за пределами видимой области сверху/снизу (плавность скролла) |
| `maxBodyHeight` | `number` | `480` | Высота прокручиваемой области (внутренний скролл-контейнер) |

**Чистая функция (ядро, под TDD):**

```ts
export function computeVirtualWindow(params: {
  scrollTop: number;
  viewportHeight: number;
  rowHeight: number;
  rowCount: number;
  overscan: number;
}): { startIndex: number; endIndex: number; padTop: number; padBottom: number };
```
- `startIndex` = `max(0, floor(scrollTop / rowHeight) - overscan)`
- `endIndex` = `min(rowCount, ceil((scrollTop + viewportHeight) / rowHeight) + overscan)` (полуоткрытый интервал, для `slice`)
- `padTop` = `startIndex * rowHeight`
- `padBottom` = `(rowCount - endIndex) * rowHeight`

**Рендер:** прокрутка — внутренний `div` c `max-height: maxBodyHeight; overflow:auto` и обработчиком `onScroll`, обновляющим `scrollTop` в state. В `<tbody>`: строка-распорка высотой `padTop` → видимые строки `rows.slice(startIndex, endIndex)` → строка-распорка `padBottom`. (Внешний windowScroller, как в легаси, сложнее и менее самодостаточен — для нового примитива выбран внутренний контейнер.)

**Когда `virtualized` выключено** — текущий путь рендера без изменений.

## Ресайз колонок — интерфейс и поток данных

**Новые пропсы:**

| Проп | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `resizableColumns` | `boolean` | `false` | Включает перетаскиваемые границы колонок |
| `columnWidths` | `Record<string, number>` | `{}` | Текущие ширины колонок по `id` (контролируется снаружи) |
| `onColumnWidthsChange` | `(widths: Record<string, number>) => void` | — | Вызывается при изменении ширины |

**Чистая функция (под TDD):**

```ts
export function applyColumnResize(
  widths: Record<string, number>,
  columnId: string,
  deltaPx: number,
  minWidth: number,
): Record<string, number>;
```
Возвращает новый map: `base = widths[columnId] ?? minWidth`; ширина `columnId` = `max(minWidth, base + deltaPx)`. Минимальная ширина — `48px`. Детерминирована и при отсутствующем `columnId` (база = `minWidth`). На практике обработчик при `onMouseDown` сначала записывает измеренную из DOM текущую ширину в `widths`, поэтому при перетаскивании `columnId` уже присутствует; fallback на `minWidth` — только страховка.

**Рендер:** в каждой `<th>` (resizable-колонки) — тонкая перетаскиваемая граница справа. `onMouseDown` запоминает стартовый X и ширину; `mousemove`/`mouseup` (на window) считают `deltaPx`, зовут `applyColumnResize`, отдают результат через `onColumnWidthsChange`. Ширина применяется как inline-`style` на `<th>`/`<col>`.

**Хранение — на стороне вызова.** Примитив не знает про localStorage. Существующий хук `useMemorizedColumnsWidths(tableName)` возвращает `[get, save, handleColumnResizing]`; на следующем слайсе вызов передаст `columnWidths={get}` и `onColumnWidthsChange={save}`.

## Краевые случаи и обработка ошибок

- Пустой список → показываем `emptyState` (как сейчас), виртуализацию не применяем.
- `loading` → скелет-строки как сейчас; виртуализация не применяется во время загрузки.
- Минимальная ширина колонки `48px` — нельзя схлопнуть.
- Фиксированная высота строки: контент предполагается однострочным (денежные/текстовые ячейки уже такие, как в легаси с фикс. высотой).
- `virtualized` без `maxBodyHeight` → используется дефолт `480`.

## Тестирование

- **Vitest, чистые функции:**
  - `computeVirtualWindow`: верх списка (`scrollTop=0`), середина, низ (клампинг `endIndex` по `rowCount`), `overscan` расширяет окно, `padTop+видимые*rowHeight+padBottom === rowCount*rowHeight`.
  - `applyColumnResize`: увеличение, уменьшение, клампинг по `minWidth`, отсутствующий `columnId` (берётся база).
- **Гейты:** `pnpm typecheck` (3 пакета), `node packages/webapp/scripts/lang-check.js` (EN===RU), полный `pnpm --filter @bigfin/webapp exec vitest run` (старые тесты + новые; «All»-таблица не сломана, т.к. пропсы опциональны).
