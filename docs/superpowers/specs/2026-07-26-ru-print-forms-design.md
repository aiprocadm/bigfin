# Печатные формы РФ (②c) — дизайн — 2026-07-26

> Под-проект ②c дорожной карты v5 (`2026-06-29-roadmap-actualization-v5.md`, §5 п.1).
> Scope из v2-карты: Счёт на оплату, Акт выполненных работ, УПД, ТОРГ-12, Счёт-фактура +
> UI выбора формы при печати. Зависимость ②a (реквизиты) — выполнена.

## Решения

1. **Поэтапно, по одной форме на PR.** Фаза 1 — «Счёт на оплату» (универсален для всех
   налоговых режимов, самая частая форма). Дальше: Акт → УПД → ТОРГ-12 → Счёт-фактура.
2. **Отдельный серверный модуль `RuPrintForms`** (`packages/server/src/modules/RuPrintForms/`),
   а не расширение SaleInvoices: у РФ-форм своя логика реквизитов, свои шаблоны и свой
   feature-флаг; существующий PDF-пайплайн (branding-шаблоны, кастомайзер) не трогаем.
3. **Реквизиты организации** читаются напрямую из `tenants_metadata` через `TenancyContext`
   (поля ②a: `legalForm, taxRegime, inn, kpp, ogrn, bankName, bankBik, bankAccount,
   bankCorrespondentAccount`). Сервис `GetOrganizationBrandingAttributes` не расширяем —
   он обслуживает пользовательские branding-шаблоны, где эти поля не редактируются.
4. **Реквизиты контрагента**: фаза 1 использует `contact.inn` (единственное поле, которое
   уже есть в модели). Подключение `kpp/ogrn/bank_*` из уже существующих колонок `contacts`
   в модель/DTO — отдельная задача в фазе 2 (нужна для УПД/Счёта-фактуры).
5. **Шаблон** — новый компонент `RuPaymentInvoicePaperTemplate` в `shared/pdf-templates`
   (React SSR → Gotenberg, как остальные). Вёрстка — обычные `<table>` с инлайн-стилями:
   форма нормативная, пользовательской настройки цветов/лого не требует.
   Кириллический шрифт уже вшит (`_fonts.ts`).
6. **Тексты формы — фиксированные русские константы в шаблоне**, не через i18n организации:
   это юридическая печатная форма РФ, её язык не зависит от языка интерфейса.
7. **Сумма прописью** — своя утилита `amountToWordsRu` (модуль `RuPrintForms/utils/`),
   в кодовой базе аналога нет. Род («одна тысяча», «два рубля»), склонения, копейки цифрами
   («00 копеек» — как в типовой форме). Формат чисел — `1 500,00` (`formatMoneyRu`).
8. **Эндпоинт**: `GET /ru-print-forms/sale-invoices/:id/payment-invoice`.
   Content negotiation как у SaleInvoices: `Accept: application/pdf` → PDF,
   иначе `{ htmlContent }`. Права — те же, что просмотр инвойса
   (`SaleInvoiceAction.View`). Пустой `Accept`/JSON — тоже `{ htmlContent }`.
9. **Feature-флаг** `ru_print_forms` (default off), в `MODULE_ALLOWLIST` (тумблер на
   странице «Модули»), проверка в контроллере через `FeaturesManager.accessible()`
   (паттерн VatAnalysis). Одним флагом закрываются все будущие формы ②c.
10. **НДС в счёте**: если у инвойса есть `taxes` — строка «В том числе НДС: …» (сумма
    `taxAmountWithheld`), иначе «Без налога (НДС)» (типовой вид для УСН).
11. **`renderSSR`** параметризуется (`lang`, `title`) с прежними дефолтами — сейчас
    захардкожен `lang="en"` / `<title>Invoice</title>`.

## Вид формы «Счёт на оплату» (фаза 1)

Типовой макет (как у 1С/Fintablo):

1. Банковская таблица-шапка: Банк получателя / БИК / Сч. № (корсчёт) / ИНН / КПП /
   Получатель / Сч. № (расчётный).
2. Заголовок «Счёт на оплату № {номер} от {дата}» + отбивка.
3. «Поставщик (Исполнитель): {название}, ИНН {…}, КПП {…}, {адрес}»;
   «Покупатель (Заказчик): {название}{, ИНН …}{, адрес}».
4. Таблица позиций: № / Товары (работы, услуги) / Кол-во / Ед. / Цена / Сумма.
5. Итоги: Итого / Без налога (НДС) | В том числе НДС / Всего к оплате.
6. «Всего наименований N, на сумму … руб.» + сумма прописью (капитализирована).
7. Подписи: Руководитель ________ / Бухгалтер ________.

Пропуски данных не валят генерацию: незаполненные реквизиты → пустые ячейки
(пользователь ещё не ввёл ИНН — счёт всё равно печатается).

## Не входит в фазу 1

- UI-выбор формы при печати (появится, когда форм станет ≥2) — пока отдельная кнопка
  «Счёт (РФ)» в панели действий инвойса за флагом.
- Акт/УПД/ТОРГ-12/Счёт-фактура (фазы 2–4), альбомная ориентация (`PageProperties`
  прокинем в фазе ТОРГ-12/УПД).
- UI ввода реквизитов организации на странице «Общие» (сервер принимает, формы нет) —
  отдельная задача, отмечена в плане.
- ЭДО, фирменный бланк с лого — за пределами ②c (по v2-карте).
