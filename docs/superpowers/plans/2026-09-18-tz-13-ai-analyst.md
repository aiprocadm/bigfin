# ТЗ, этап 13 «ИИ-аналитик» — план и приёмка

ТЗ само называет §13.1 «жёсткими ограничениями, нарушение = откат этапа».
Поэтому почти весь этап — про то, чего модели делать НЕ дают.

## Главная мысль этапа

Модель хорошо формулирует и плохо считает. Если попросить её посчитать, она
сложит суммы «в уме» и иногда ошибётся — а **неверное число выглядит ровно
так же, как верное**. Человек примет решение по цифре, которой нет ни в одном
отчёте, и никогда не узнает, откуда она взялась.

Отсюда два слоя защиты, оба проверены мутацией:

1. **Разрешительный сбор данных.** В модель уходят только перечисленные поля:
   название, суммы, доля, ссылка. Не «запрещаем плохое», а «разрешаем
   известное хорошее» — забыть добавить поле безопасно, забыть запретить нет.
2. **Сверка каждого числа из ответа** с числами, которые мы модели дали. Не
   сошлось — наблюдение выбрасывается целиком.

## Что сделано

| Правило | Почему |
|---|---|
| Список полей **разрешительный** | запретительный пропустил бы первое же новое поле, которое кто-нибудь добавит в агрегат, — и пропустил бы молча |
| Приватное поле **ломает** сборку промпта | тихая вычистка означала бы, что настоящую утечку мы бы «починили» незаметно для себя |
| Проверка стоит в единственной точке сборки промпта | поставь её в вызывающем коде — и однажды появится второй вызывающий, который забудет |
| Число из текста сверяется с данными | §13.4 «Ни одно число в тексте не расходится с отчётом» |
| Допуск относительный (1%) | агрегат 2 803 411 ₽ человек читает как «2,8 млн»; точное совпадение выбросило бы все живые формулировки |
| Мелкие целые (≤12) не сверяются | «третий месяц», «в 2 раза» — это не утверждения о суммах |
| Наблюдение без ссылки отбраковывается | §13.1 п. 3; непроверяемое утверждение о деньгах хуже молчания |
| Недобор **не добирается** выброшенными | иначе в отчёт вернулись бы ровно те выводы, которые мы признали недостоверными, — лишь бы набрать «3–5» |
| Флаг `ai_analyst` выключен по умолчанию | §13.1 п. 4 |
| Запрет на внешние сервисы **закрывает раздел с объяснением** | §13.1 п. 5: «недоступен, а не деградирует молча». Пустой блок «Что говорят цифры» выглядит так же, как блок, которому нечего сказать |
| Локальная модель запретом не перекрывается | запрет ею УДОВЛЕТВОРЯЕТСЯ: локальная модель никуда данные не отправляет |
| Чужой адрес не выдаёт себя за локальную модель | иначе под видом «своей модели» данные уехали бы наружу в обход запрета |
| Кривой адрес НЕ считается локальным | ошибка разбора — не повод разрешить отправку |
| Неизвестный провайдер = «выключено» | опечатка в настройке не должна ронять главную страницу |
| Ненастроенный провайдер **говорит** об этом | пустой ответ выглядел бы как «модели нечего сказать» |
| Пустое поле ключа не стирает сохранённый ключ | иначе открытие формы и «Сохранить» ломали бы рабочую интеграцию |
| Суточный кеш, чтение только из него | §13.3; иначе десять человек за утро оплатили бы десять одинаковых ответов, каждый подождав по несколько секунд |
| В кеше хранятся счётчики «предложено/отбраковано» | без них невозможно понять, что модель начала врать: на экране-то остаются только принятые |
| Сбой одного раздела не роняет остальные | модель могла не ответить на один запрос |

### Провайдеры (§13.2)

`AiProvider` за интерфейсом, четыре реализации: YandexGPT, GigaChat,
OpenAI-совместимая (в том числе своя, локальная) и заглушка «выключено».
Ключи и адреса — в настройках организации, не в коде: ключ в коде означал бы,
что все покупатели ходят в модель через наш счёт, а тот, кто ставит продукт
на свой сервер, не может подключить свою модель.

### Разбор ответа

Модель почти всегда оборачивает JSON в пояснения и ограждение, хотя её просили
этого не делать. Разбор это переживает — сутки без выводов из-за лишней строки
плохой обмен. Но неразобранный ответ даёт **пусто**, а не выдуманные
наблюдения.

## Мутация

- Разрешительный список полей превращён в запретительный → 2 теста красные.
- Снята сверка чисел с отчётом → 3 теста красные.

Обе защиты возвращены, прогон зелёный.
