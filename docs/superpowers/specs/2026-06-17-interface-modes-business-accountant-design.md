# ③ Режимы интерфейса «Бизнес» / «Бухгалтер» (MVP) — дизайн

**Дата:** 2026-06-17
**Под-проект роадмапа:** ③ (раздел `2026-05-27-fintablo-planfact-parity-roadmap.md`, §4.2)
**Статус:** дизайн утверждён, готов к плану реализации
**Флаг:** `interface_modes` (default off)

---

## 1. Зачем

Аудитория Bigfin — предприниматели **без бухгалтерского образования**; основатель сам пользователь (dogfooding). Сейчас при входе видны чисто-бухгалтерские экраны (ручные проводки, оборотно-сальдовая, главная книга и т.п.), которые пугают непрофи. Пункт ③ роадмапа должен прятать их за переключателем режима.

**Проверка-вывод (2026-06-17):** ③ ранее НЕ был реализован, хотя сводный мастер-план считал зависимость «удовлетворённой». Команда подменила концепцию ③ на per-модульные feature-флаги — это закрыло видимость *новых* модулей, но НЕ спрятало легаси-бухгалтерию. Эта спека закрывает реальный пробел.

## 2. Объём (MVP)

Один организационный флаг `interface_mode: 'business' | 'accountant'`, который **только на фронте** прячет набор легаси-бухгалтерских экранов. Двойная запись и все расчёты — без изменений.

### Что прячется в режиме «Бизнес» (6 экранов)

| Экран | Маршрут | Где в меню |
|---|---|---|
| Ручные проводки | `/manual-journals` | Учёт → Финансы |
| Сделать проводку | `/make-journal-entry` | Учёт → новые задачи |
| Журнал проводок | `/financial-reports/journal-sheet` | Отчёты |
| Главная книга | `/financial-reports/general-ledger` | Отчёты |
| Оборотно-сальдовая ведомость | `/financial-reports/trial-balance-sheet` | Отчёты |
| Закрытие периодов | `/transactions-locking` | Учёт → Финансы |

### Остаётся видимым в обоих режимах

План счетов (`/accounts`), Ставки налогов (`/tax-rates`), Баланс, ОПиУ, ДДС, дебиторка/кредиторка (aging), отчёты по товарам/контрагентам и всё остальное.

### Поведение по умолчанию

- Значение режима не задано → трактуется как **`business`** (все организации, новые и существующие).
- Меняется в любой момент в Настройках.

### Строгость скрытия

Скрытый экран **убирается из меню И** при заходе по прямой ссылке/закладке — **редирект на главную** (`/`). «Скрыто — значит скрыто».

## 3. Архитектура

### Хранение
Поле `interface_mode` (varchar, nullable) в таблице `tenants_metadata` (**system schema** — рядом с `language`, `base_currency`; см. соглашение про организационные данные). Отсутствие значения = `business` (нормализуется при чтении, без бэкфилла существующих строк).

### Бэкенд (3 точки)
1. **Миграция (system):** `tenants_metadata.interface_mode` — nullable varchar, рабочий `down()`.
2. **`GetCurrentOrganizationTransformer`:** добавить в ответ поле `interfaceMode`, нормализуя пустое значение → `'business'`. Поле доезжает на фронт через существующий `GET /organization/current`.
3. **`UpdateOrganizationDto` + `UpdateOrganizationService`:** принять опциональный `interfaceMode` с валидацией enum (`business`|`accountant`) и сохранить в metadata. Переиспользуется существующий `PUT /organization`.

### Фронт (4 точки)
1. **Хук `useInterfaceMode()`** — читает `interfaceMode` из текущей организации (там же, откуда берутся язык/валюта).
2. **Меню:** пометить 6 пунктов в `constants/sidebarMenu.tsx` свойством `accountantOnly: true`; добавить предикат `predMode` в `useFilterSidebarMenuAbility` (`containers/Dashboard/Sidebar/hooks.tsx`) рядом с `predFeature`/`predAbility`. Предикат отбрасывает `accountantOnly`-пункт, когда режим = `business`. Один фильтр покрывает и главное боковое меню, и под-меню (оба используют `useFilterSidebarMenuAbility`).
3. **Гард маршрутов:** обёртка для 6 легаси-маршрутов в `routes/dashboard.tsx` — редирект на `/`, если режим `business`. Список «accountant-only» маршрутов держать рядом со списком меню-ключей (единый источник, чтобы не разъехались).
4. **Переключатель:** карточка «Режим интерфейса» (две опции «Бизнес»/«Бухгалтер») на странице Настроек (Preferences). Сохранение через `PUT /organization`. Видимость/право менять — по существующему гейту страницы Preferences (`PreferencesAbility.Mutate`).

### Feature-флаг
`Features.INTERFACE_MODES = 'interface_modes'` (default **off**), запись в `FeaturesConfigure` + spec по образцу. Когда флаг **off** — предикат `predMode` и гард маршрутов считают режим неактивным (всё видно, текущее поведение). Когда **on** — режим применяется (по умолчанию `business`). Это «мягкий гейт» — управляет только видимостью на фронте; модуль/эндпоинты всегда доступны.

## 4. Чистые функции (для тестов)

- `isAccountantOnlyHiddenInMode(mode, isFeatureOn) → boolean` — единственное место правды: «надо ли прятать accountant-only экран». Используется и предикатом меню, и гардом маршрута. Покрыта unit-тестами (off-флаг → не прячем; on+business → прячем; on+accountant → не прячем).

## 5. Тесты

- **Бэкенд (Jest):** `UpdateOrganizationDto` отвергает посторонние значения режима; transformer отдаёт `business` при пустом metadata; `FeaturesConfigure.interface_modes.spec.ts` (default off).
- **Фронт:** unit-тест чистой функции `isAccountantOnlyHiddenInMode` (матрица флаг×режим).

## 6. i18n

Ключи `interface_mode.*` (EN+RU парно, через `intl.get`): заголовок карточки, подписи «Бизнес»/«Бухгалтер», поясняющий текст, тост сохранения. После правок — `node packages/webapp/scripts/lang-check.js`.

## 7. Сознательно НЕ входит (anti-scope)

- **Онбординг-визард** (тип бизнеса услуги/товары/смешанное, наличие НДС, наличие сотрудников → дефолтный набор статей и видимость модулей) — отдельный под-проект ③-onboarding.
- **Режим на каждого пользователя** (бухгалтер видит бухгалтерию, директор — нет в одной организации) — будущее; сейчас режим организационный.
- **Скрытие плана счетов и ставок налогов** — оставлены видимыми по решению основателя.
- **Блокировка API** скрытых сущностей — прячем только в интерфейсе (`ручные проводки` и пр. API используются внутренними потоками).

## 8. Пути и соглашения

- Миграция: `packages/server/src/database/system/migrations/` (через скилл `make-migration`, корректный timestamp), рабочий `down()`. Локально БД может не подняться — прогон `latest→rollback→latest` на CI/staging.
- Только `Bigfin` в строках. Любая видимая строка — через i18n.
- Node 18.16.1 + pnpm. Приёмка: `pnpm --filter @bigfin/server test` + `pnpm typecheck` + `lang-check.js`.

## 9. Критерий завершения

1. Флаг `interface_modes` off → всё видно, поведение не изменилось (регрессий нет).
2. Флаг on + режим `business` → 6 экранов исчезли из меню; заход по прямой ссылке редиректит на `/`.
3. Переключение на `accountant` в Настройках → 6 экранов вернулись (после сохранения).
4. Существующие организации без значения режима трактуются как `business`.
5. `typecheck` (3 пакета), серверные тесты, `lang-check` — зелёные.
