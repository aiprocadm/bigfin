# Публичный API Bigfin

Это документация для тех, кто хочет связать Bigfin со своей программой:
выгрузить отчёт, завести операцию, получать уведомления о событиях.

Живой список всех ручек — Swagger UI по адресу `/api/docs`. На боевом сервере
он открывается только при явно выставленной переменной `API_DOCS_ENABLED=true`:
молчание означает «закрыто», чтобы забытая настройка не выставила наружу
полный перечень ручек.

---

## 1. Токен

Токен — это ключ от всех денег организации. Обращайтесь с ним как с паролем.

**Где взять:** Настройки → Публичный API → Выпустить токен.

При выпуске выбираются:

- **Название** — чтобы через год было понятно, что отзываете.
- **Права** — что этому токену можно. Выдавайте минимум: интеграции, которая
  только забирает отчёты, не нужно право менять операции.
- **Срок жизни** — необязателен.

**Токен показывается ровно один раз.** Дальше его нет нигде: ни в базе, ни в
списке, ни в журналах — у нас хранится только его отпечаток. Потеряли —
выпустите новый и отзовите старый. Это неудобно и сделано намеренно: если бы
токен можно было подсмотреть повторно, значит, он лежал бы у нас целиком, и
утечка базы отдала бы доступ ко всем организациям сразу.

### Права

| Право | Что разрешает |
|---|---|
| `reports:read` | Читать отчёты |
| `transactions:read` | Читать операции |
| `transactions:write` | Создавать и изменять операции |
| `contacts:read` | Читать контрагентов |
| `contacts:write` | Создавать и изменять контрагентов |
| `invoices:read` | Читать счета |
| `invoices:write` | Создавать и изменять счета |

Права «можно всё» нет намеренно. И **пустой список прав — это не «можно
всё»**: такой токен не пройдёт ни одной проверки. Так задумано, чтобы токен,
у которого забыли проставить права, не получал их по умолчанию.

### Отзыв

Токен **отзывается**, а не удаляется. Отозванный остаётся видимым в списке и
больше не работает. Удалённый исчез бы вместе с ответом на вопрос «кто и когда
им пользовался» — а этот вопрос как раз и задают после утечки.

## 2. Как обращаться к API

Токен передаётся в заголовке `Authorization`:

```bash
curl https://app.bigfin.ru/api/reports/balance-sheet \
  -H "Authorization: Bearer bgf_ваш_токен" \
  -H "organization-id: ваш_идентификатор_организации" \
  -H "Accept: application/json" \
  -G \
  --data-urlencode "fromDate=2026-01-01" \
  --data-urlencode "toDate=2026-12-31"
```

Список операций по всем счетам (право `transactions:read`):

```bash
curl https://app.bigfin.ru/api/banking/transactions \
  -H "Authorization: Bearer bgf_ваш_токен" \
  -H "organization-id: ваш_идентификатор_организации" \
  -G --data-urlencode "fromDate=2026-09-01" --data-urlencode "toDate=2026-09-30"
```

Создание операции (право `transactions:write`). `cashflowAccountId` — денежный
счёт (банк, касса), `creditAccountId` — счёт статьи, `transactionType` — вид
операции: `OtherExpense` (расход), `OtherIncome` (приход), `OwnerContribution`,
`OwnerDrawing`, `TransferToAccount`, `TransferFromAccount`:

```bash
curl -X POST https://app.bigfin.ru/api/banking/transactions \
  -H "Authorization: Bearer bgf_ваш_токен" \
  -H "organization-id: ваш_идентификатор_организации" \
  -H "Content-Type: application/json" \
  -d '{
    "date": "2026-09-18",
    "transactionType": "OtherExpense",
    "amount": 15000,
    "cashflowAccountId": 12,
    "creditAccountId": 47,
    "description": "Оплата за сентябрь"
  }'
```

### На TypeScript

Типы и функции-запросы собираются из той же спеки, что и Swagger UI, —
пакет `@bigfin/sdk-ts` в папке `shared/sdk-ts` этого репозитория (в npm он не
публикуется). Адрес в `baseUrl` — без `/api`: пути в пакете уже начинаются с него.

```ts
import { createApiFetcher, fetchBalanceSheetJson } from '@bigfin/sdk-ts';

const fetcher = createApiFetcher({
  baseUrl: 'https://app.bigfin.ru',
  init: {
    headers: {
      Authorization: `Bearer ${process.env.BIGFIN_TOKEN}`, // токен НЕ хранят в коде
      'organization-id': process.env.BIGFIN_ORG!,
      Accept: 'application/json',
    },
  },
});

// Баланс на конец года.
const report = await fetchBalanceSheetJson(fetcher, {
  fromDate: '2026-01-01',
  toDate: '2026-12-31',
});
```

Для ручек, у которых в пакете нет готовой функции, есть `rawRequest(fetcher,
'POST', '/api/banking/transactions', тело)`.

### Ответы об ошибке

Тело ошибки всегда одной формы: `{ "errors": [{ "type": "…", "message": "…" }] }`.

| Ответ | `type` | Что случилось |
|---|---|---|
| 401 | `API_TOKEN_INVALID` | Такого токена нет. Подробностей нет намеренно: перебирающему токены не нужно знать, насколько он близок. |
| 403 | `API_TOKEN_INACTIVE` | Токен отозван или истёк. Это знает только тот, у кого токен уже был, поэтому говорим прямо — выпустите новый. |
| 403 | `API_SCOPE_MISSING` | У токена нет нужного права — в тексте сказано, какого. |
| 403 | `API_SCOPE_NOT_AVAILABLE` | Эта ручка по токену недоступна вовсе (например, настройки организации). |
| 403 | `API_TOKEN_ORGANIZATION_MISMATCH` | Токен выпущен для другой организации, чем в заголовке `organization-id`. |

Кроме прав токена действуют права его владельца: токен сотрудника не видит
больше, чем сам сотрудник, включая ограничения его роли по статьям,
направлениям и счетам.

## 3. Вебхуки

Вебхук — это обратная сторона API: не вы спрашиваете нас, а мы сообщаем вам,
что что-то произошло. Вы даёте адрес, мы присылаем на него POST-запрос.

**Где настроить:** Настройки → Публичный API → Вебхуки.

### События

| Событие | Когда приходит |
|---|---|
| `transaction.created` | Появилась новая операция |
| `transaction.article_changed` | У операции сменили статью |
| `payment_request.approved` | Заявку на оплату согласовали |
| `cash_gap.forecasted` | В прогнозе появился кассовый разрыв |

### Адрес

Адрес должен быть внешним и начинаться с `http://` или `https://`. Внутренние
адреса (`localhost`, `10.*`, `192.168.*`, `169.254.169.254` и подобные)
запрещены: по такому адресу вебхук всё равно не дойдёт, а вот наш сервер
можно было бы заставить сходить внутрь нашей же сети.

### Подпись — обязательно проверяйте

При создании подписки выдаётся **секрет** (тоже один раз). Каждый наш вызов
подписан этим секретом. Адрес вашего вебхука рано или поздно узнают, и без
проверки подписи любой сможет прислать вам «кассовый разрыв».

Заголовки запроса:

```
X-Bigfin-Event: transaction.created
X-Bigfin-Timestamp: 1800000000
X-Bigfin-Signature: <шестнадцатеричная строка>
```

Подпись — это HMAC-SHA256 от строки `<timestamp>.<тело запроса>`:

```ts
import { createHmac, timingSafeEqual } from 'crypto';

function verify(body: string, headers: Record<string, string>, secret: string) {
  const timestamp = Number(headers['x-bigfin-timestamp']);

  // 1. Свежесть. Подпись старше 5 минут не принимается, даже если она
  //    верная: иначе перехваченный вызов можно повторять бесконечно.
  if (!Number.isFinite(timestamp)) return false;
  if (Math.abs(Math.floor(Date.now() / 1000) - timestamp) > 300) return false;

  // 2. Сама подпись. Сравнение постоянного времени: обычное сравнение
  //    выходит на первом различии, и подпись подбирается посимвольно.
  const expected = createHmac('sha256', secret)
    .update(`${timestamp}.${body}`)
    .digest('hex');

  const a = Buffer.from(expected, 'hex');
  const b = Buffer.from(headers['x-bigfin-signature'] ?? '', 'hex');

  return a.length === b.length && timingSafeEqual(a, b);
}
```

Важно: подписывается **тело вместе со временем**. Если бы подписывалось
только тело, подпись годилась бы навсегда.

### Повторные попытки

Ответьте кодом 2xx — доставка считается успешной.

| Ваш ответ | Что делаем |
|---|---|
| 2xx | Готово |
| 5xx или нет ответа | Повторяем |
| 408, 429 | Повторяем (вы сами просите) |
| Прочие 4xx | **Не повторяем** — запрос не станет верным от повтора |

Повторов до 6, задержка удваивается: 30 с, 60 с, 2 мин, 4 мин, 8 мин. Ровные
повторы добивали бы сервер, который и так лежит: он поднялся бы и тут же
получил шквал накопившихся вызовов.

История доставок видна в настройках подписки — там же ответ на вопрос
«почему мне не пришло событие?».

## 4. MCP-сервер для ИИ-агентов

MCP (Model Context Protocol) — общий язык, на котором ИИ-агенты (Claude, GPT,
Yandex AI Studio и другие) подключают внешние данные. Bigfin отвечает на нём по
адресу `https://app.bigfin.ru/api/mcp` (транспорт «streamable HTTP»).

- **Вход — тем же токеном `bgf_` и заголовком `organization-id`.** Агент
  видит ровно то, что разрешено токену и его владельцу, включая ограничения
  роли по статьям, направлениям и счетам.
- **Только чтение.** Каждый инструмент — один вызов уже существующей ручки
  API, поэтому числа совпадают с экраном по построению.
- **Каждый ответ несёт `meta`**: период, фильтры, юрлица, валюту и время
  расчёта. Агенту не нужно угадывать контекст.
- **Не больше 60 вызовов инструментов в минуту на токен.** Защита от
  зациклившегося агента.

| Инструмент | Что возвращает | Право токена |
|---|---|---|
| `get_cash_flow` | Деньги по статьям (ОДДС); без дат — прошлый месяц | `reports:read` |
| `get_managerial_pnl` | Управленческий ОПиУ с ярусами МД → ВП1 → ВП2 → ОП → ЧП | `reports:read` |
| `get_balance_sheet` | Баланс | `reports:read` |
| `get_cash_gaps` | Прогноз кассовых разрывов по счетам | `reports:read` |
| `get_debts` | Долги нам и наши, просрочка | `reports:read` |
| `list_transactions` | Операции по денежным счетам | `transactions:read` |
| `get_articles` | Справочник статей | `reports:read` |
| `get_budget_plan_fact` | План-факт бюджета | `reports:read` |

Готовые настройки для подключения — в Настройках → Публичный API →
«MCP-сервер для ИИ-агентов», там же журнал последних вызовов.

Агенты, которые умеют MCP по HTTP:

```bash
claude mcp add --transport http bigfin https://app.bigfin.ru/api/mcp \
  --header "Authorization: Bearer bgf_ваш_токен" \
  --header "organization-id: ваш_идентификатор_организации"
```

Claude Desktop говорит с серверами через stdio — ему нужен мост `mcp-remote`
(см. готовый `claude_desktop_config.json` на экране настроек).

Проверить вручную:

```bash
curl -X POST https://app.bigfin.ru/api/mcp \
  -H "Authorization: Bearer bgf_ваш_токен" \
  -H "organization-id: ваш_идентификатор_организации" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"get_cash_flow","arguments":{"fromDate":"2026-08-01","toDate":"2026-08-31"}}}'
```

## 5. Что держать в голове

- Токен и секрет вебхука не хранят в коде и не кладут в репозиторий —
  только в переменных окружения.
- Выдавайте токену минимум прав.
- Всегда проверяйте подпись вебхука, включая срок её свежести.
- Ваш обработчик вебхука должен переживать повторную доставку одного и того
  же события: повтор возможен, если ваш ответ не дошёл до нас.
