# Bigfin — Дорожная карта v18 «Рубль, точка, подпись» — 2026-08-22

Карта v17 «Русский продукт с русским курсом» закрыта целиком (#286–#298):
курс ЦБ РФ с курсом на дату, русификация ~330 строк UI (кластеры A–H),
форма товара, подписанты печатных форм. Из v17 открытыми остались только
решения владельца: 21 (демо-режим), 27 (подписки), 32 (тексты privacy/terms).
Хвост v7/v9 прежний — GitHub Actions выключены до сентября 2026, все
проверки гоняются вручную.

---

## 1. Итог фазы v17 — одним абзацем

Продукт перестал зависеть от платного зарубежного курса (официальный ЦБ РФ,
бесплатно, с курсом на дату документа — живьём до копейки) и перестал
говорить с пользователем по-английски: семь срезов русификации закрыли все
живые экраны (~330 строк), включая публичную страницу оплаты, брендирование,
банк, налоги и экспорт. Форма товара больше не ломает новичка (склад только
для товаров, счета в свёрнутой «Бухгалтерии», починенный префил), а печатные
формы обзавелись подписантами. Приёмкой каждого среза были живые пробы.

---

## 2. Что дала разведка этой итерации

Два направления разведки + свои пробы на стенде (свежая организация
fresh2@). Хорошая новость: «организация рождается русской» уже больше чем
наполовину — план счетов переводится по языку организации (34/34 русских
имени), сид налоговых ставок чисто русский (НДС-линейка), мастер по
умолчанию RUB+ru, письма клиентам базово русские (mail.json полный, язык
берётся из метаданных организации). Остатки — счётные и точечные.

### Линия 1. Суммы: «RUB100 000,00» вместо «100 000,00 ₽»

Вебаппный `formattedAmount` (`packages/webapp/src/utils/index.tsx:188-211`)
берёт из `js-money` поле `symbol` (для RUB это строка «RUB», настоящий ₽
лежит в `symbol_native`) и жёстко ставит знак ПЕРЕД суммой (`%s%v`), заодно
перекрывая правильные глобальные настройки из `configureAccountingForLocale`.
Потребители: компонент `<Money>` (29 использований) + 62 прямых вызова —
итоги форм, списки чеков/смет/платежей/контрагентов, дроверы. **Правка
точечная: одна функция, 91 место чинится автоматически.** Эталон уже написан
и покрыт тестами на сервере: `packages/server/src/utils/format-number.ts`
(`symbol_native`, `%v NBSP %s` для RUB) + `format-number.spec.ts`
(«590 000,00 ₽»). Списки V2 счетов/биллов уже сознательно берут серверные
`*_formatted` — их не трогать.

### Линия 2. Даты: «28.07.2026» выбрать физически нельзя

Русского формата с точками нет ни в выпадашке настроек
(`Miscellaneous.constants.ts`), ни в валидации DTO
(`Organization.constants.ts` `@IsIn`) — только слэш-варианты; прямой PUT
с `DD.MM.YYYY` отвергается. Дефолт новой организации — `DD MMM YYYY`, а
**на сервере локаль moment не переключается** → в списках «28 Jul 2026»
с английским месяцем. Фолбэк трансформера — `DD-MM-YYYY`. Клиентский путь
(`FormatDate` + карта `date_formats` в словаре) уже русифицирован. Ещё:
два мёртвых дубля списков форматов (легко править не тот файл) и шесть мест
`<FormatDate value={*_formatted}>` — двойное форматирование уже
отформатированной строки.

### Линия 3. Письма клиентам: базово русские, остался «Discount» и лежачий хлам

Темы/тела/лейблы/кнопки уже переводятся по языку организации
(`OrganizationI18nService`, `mail.json`), PDF-вложение локализовано.
Остатки:
- **Реальный баг у клиента:** `transformInvoiceToPdfTemplate` спредится
  ПОСЛЕ переведённых лейблов и затирает их хардкодом
  `'Discount [10%]'`/`'Discount'` — в клиентском PDF счёта и чека
  (`SaleInvoices/utils.ts:47-50`, `SaleReceipts/utils.ts:25-27`) и в трёх
  превью почты (`Get*MailState.transformer.ts`). Итого 5 мест.
- `<Html lang="en">` захардкожен в layout всех писем
  (`shared/email-components/src/lib/EmailTemplateLayout.tsx:12`).
- Английские дефолты пропсов в 4 компонентах писем (страховка, не текущий
  баг) и кнопка `Close` + английские имена переменных («Customer Name») в
  дровере отправки.
- Мёртвое: константы `DEFAULT_*_MAIL_*` в 4 модулях (не подставляются
  никуда, но выглядят источником правды), ключи `mail.invoice.reminder_*`,
  компонент `CreditNoteEmailTemplate` без серверного потока отправки.

### Линия 4. Рождение организации: счётный хвост английского

- **7 описаний счетов** в сиде — сырые английские предложения без ключей
  (`seeds/data/accounts.ts:174,216,241,252,273,332,390`); имена все на
  ключах и переведены.
- **«Ленивые» счета из рантайма**: `Accounts.constants.ts` — параллельный
  английский набор; `Account.repository.ts` создаёт `Stripe Clearing`
  по-английски, а для валютных дебиторки/кредиторки зовёт ключи
  `account.accounts_receivable.currency`, **которых нет ни в en, ни в ru**
  — в базу ляжет сам ключ. Плюс мёртвый английский `SeedAccounts`.
- **~35 английских имён стандартных представлений** («Draft», «Unpaid»,
  «Overdue»…) в 10 файлах `*/constants.ts` — механика перевода есть
  (i18n.t по языку запроса), кредит-ноты уже на ключах, остальные —
  литералы.
- **5 × «Standard Template»** — имена PDF-шаблонов новой организации
  (миграция `20240915195024_seed_standard_pdf_templates.ts`).
- **Имена валют всегда английские** («Russian Ruble») — сид валют берёт их
  из `js-money`.
- Первый филиал/склад локализованы, но язык берут из HTTP-запроса, а не из
  организации — в фоновой очереди упадут на английский
  (`ActivateBranchesFeature.service.ts`, `CreateInitialWarehouse.service.ts`).
- Префиксы номеров документов латинские (`INV-`, `REC-`, `CN-`… — 9 шт.) —
  спорно: латинские префиксы в РФ-практике легитимны; без решения владельца
  не трогать (вопрос 34).

### Чего в списке НЕТ (намеренно)

- **Переоценка валютных остатков** — по-прежнему без подтверждённого
  спроса не начинать (6–10 срезов); фундамент (курс на дату) готов.
- **Демо-режим (21), подписки (27), privacy/terms (32)** — ждут решений
  владельца, объёмы посчитаны в v17.
- **Тарифы «Free»/«Early Adaptor»** в системном сиде — упираются в
  вопрос 27, вместе с ним.
- **Префиксы номеров** — вопрос 34 (см. линию 4).

## 3. Вопросы владельцу (новые)

- **34. Префиксы номеров документов.** Новая организация нумерует документы
  как `INV-0001`, `REC-0001`, `CN-0001`… Латиница здесь — норма многих
  российских сервисов, но если хотите русские префиксы (`СЧ-`, `ЧК-`…) —
  скажите, поменяю сид для новых организаций (существующие не трогаются).
- **35. Отправка кредит-ноты почтой.** Компонент письма существует, но
  серверного потока отправки никогда не было (кнопки «Отправить» у
  кредит-ноты нет). Удалить мёртвый компонент — или построить поток?

## 4. Фаза «Рубль, точка, подпись» — срезы

1. **Р1 — рубль со знаком ₽.** Переписать `formattedAmount` по образцу
   серверного `format-number.ts` (symbol_native; для RUB «%v NBSP %s»),
   юнит-тест зеркалом серверного спека; `formattedExchangeRate` — на явную
   локаль. Живьём: списки чеков/смет и итоги форм показывают
   «100 000,00 ₽». **✅ Сделан (PR #300)** — 8 юнит-кейсов (красный
   проверен: 4 падали), живьём чеки demo «100 000,00 ₽», паттерн
   «RUB<цифры>» не встречается; нюанс: у иены родной знак широкий «￥»,
   как на сервере.
2. **Р2 — русская дата с точками.** `DD.MM.YYYY`+`DD.MM.YY` в оба живых
   списка; дефолт новой организации по языку (`ru` → `DD.MM.YYYY`); фолбэк
   трансформера; system-миграция существующих `tenants_metadata`
   (`DD/MM/yyyy`→`DD.MM.YYYY` только для language=ru); локаль moment на
   сервере по языку организации (месяцы «28 июл 2026» для словесных
   форматов); чистка двух мёртвых списков (по правилу «не удалять без
   спроса» — спрошу в PR); двойной формат `<FormatDate value={*_formatted}>`
   ×6. **✅ Сделан (PR #301)** — 6 юнит-кейсов (красный проверен); живьём:
   выпадашка начинается с «22.08.2026 [DD.MM.YYYY]», словесный формат
   «22 августа 2026», даты чеков «28.07.2026», миграция перевела все
   ru-организации стенда; двойной формат починен в 3 живых дроверах
   (4 в мёртвых Projects не тронуты), мёртвые списки-дубли оставлены.
3. **Р3 — письмо без Discount.** Пять мест затирания лейблов + ключ
   скидки с процентом; `lang` в `EmailTemplateLayout` из языка организации;
   дефолты пропсов писем; «Close» и переменные дровера. Мёртвые константы
   писем — предложение на удаление в PR (вопрос владельцу в тексте PR).
4. **Р4 — организация рождается русской, добивка.** 7 описаний счетов →
   ключи; починка ленивых счетов (`Stripe Clearing` → ключ, недостающие
   ключи `*_receivable.currency`); 35 имён views → ключи по образцу
   кредит-нот; «Standard Template» → «Стандартный шаблон» для новых
   (миграция-сид); русские имена валют (карта переводов поверх js-money);
   филиал/склад — язык организации.

Порядок — по видимости: Р1 (каждый список каждый день) → Р2 → Р3 (клиентский
PDF) → Р4. Каждый срез: красный тест → правка → полные прогоны → живая
проба на стенде → PR.
