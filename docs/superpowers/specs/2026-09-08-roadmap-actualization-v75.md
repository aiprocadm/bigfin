## 2. Что оказалось настоящими ошибками

Это главное. Одно замечание на файл выглядит как мелочь — а внутри лежало вот
что.

**Заголовок с организацией не отправлялся никогда.** `services/axios.tsx`
читал `state.authentication.organization`, но поле называется
`organizationId`. Значение всегда выходило пустым. Через этот путь идут
настройки, валюты и привязка данных. Основной путь (`useRequest`) читает поле
правильно — поэтому расхождение и не бросалось в глаза годами.

**Раздел настроек совпадал с любым адресом.** У маршрута стояло
`pathname="/preferences"` — такого свойства у маршрута нет вовсе, путь
оставался незаданным.

**Пункт «Поставщик» не появлялся в меню быстрого создания ни у кого.** Право
проверялось как `VendorAction.Vendor`, а такого права нет (есть View, Create,
Edit, Delete). Остальные восемь пунктов проверяют `Create`.

**Подсказка под полем не показывалась в двух формах.** Свойство назвали
`hintText`, а группа полей знает `helperText`. Обе подсказки вдобавок были
написаны по-английски прямо в коде.

**Ширина подписи не применялась.** `style={{ 'min-width': … }}` — React в
объекте оформления понимает только запись через заглавную букву, а ключ через
дефис молча выбрасывает.

**Значок «галочка вниз» не рисовался.** Файл брал `Icon` из чужого набора
(`@blueprintjs/core`), где имени `caret-down-16` нет. Все остальные места
берут наш.

**Отправка фильтра срабатывала не тогда.** `useEffect(() => debouncedSubmit)` —
отправка попадала в **возврат**, а возврат React считает уборкой.

**Поиск по счетам мог уронить экран**, если у счёта нет названия.

**Ярлык «нельзя удалить» выходил бесцветным**: `Intent.INFO` в наборе окрасок
нет, значение было пустым.

**Наш собственный многовыбор был недостижим.** Два `export *` отдавали имя
`MultiSelect`; когда так, наружу не выходит **ни один**.

Плюс мелочь, которая молчала: `.concat(undefined)` дописал бы в денежное поле
слово «undefined», если приставки в строке не нашлось.

## 3. Пятнадцать причин на сто пять файлов

| причина | файлов |
|---|---|
| `useParams()` без типа → `id` «не существует» | 12 |
| блок итогов `TotalLines` без объявленных свойств | 11 |
| адрес страницы: `parseInt(id)` при отсутствующем `id` | 11 |
| перепутанные местами имена свойств в настройке макетов | 4 |
| `R.compose` теряет знание, что на выходе компонент | 5 |
| собственные свойства оформления `--x-…` в `style` | 4 |
| область перетаскивания без объявленных свойств | 4 |
| окна отправки письма: `from` и `attachPdf` | 3 |
| `useAutofocus` без типа ссылки | 5 |
| `react-router` без типов | 3 |
| остальное — по одному-двум | ~30 |

Крупнее всех — не поломки, а **отсутствующие объявления у общих
компонентов**. Один компонент без объявленных свойств делает ошибкой каждое
место, где его вызывают. `TotalLines` — одиннадцать подвалов; область
перетаскивания — четыре формы.

## 4. Ошибка, которую я допустил и сразу поймал

Разрешая `--x-…` в оформлении, я дописал `declare module 'react'` в файл
заглушек. Файл заглушек — **не модуль** (в нём нет ни одного `import`), и такое
объявление React не дополняет, а **заменяет**: витрина рассыпалась на тысячу
ошибок вида «в React нет `useCallback`».

Это ровно та ловушка, которую карта v66 уже проходила с `react-router`. Я
наступил на неё второй раз, уже с самим React. Вынес расширение в отдельный
файл с `import 'react'` наверху и записал причину прямо в нём.

Второй раз на те же грабли — потому что вывод карты v66 был записан **про
`react-router`**, а не про правило. Теперь записан про правило.

## 5. Типы `react-router`: без установки

Трём файлам не хватало типов `react-router`. Прямая установка `@types/react-router`
потребовала бы полной переустановки зависимостей (pnpm спросил «удалить и
поставить заново?» — и висел на этом вопросе, потому что `--silent` прятал сам
вопрос).

Установка не нужна: `react-router-dom` уже стоит **с типами** и реэкспортирует
из `react-router` всё, что мы берём (`useHistory`, `Switch`, `Route`). Одиннадцать
файлов переведены на него — теперь весь продукт ходит одной дверью.

## 6. Сторож: свойства через стилевые обёртки

Сторож «свойства, которых никто не читает» (карты v59, v64, v68, v70) сравнивал
имя тега со списком **буквально**. А половина форм зовёт группу полей не по
имени, а через стилевую обёртку:

```
const TermsConditsFormGroup = styled(FFormGroup)`…`;
```

Через такую обёртку проходит всё то же самое — она пересылает свойства
дальше. В списке лежали две обёртки, вписанные руками; остальных восьми там не
было, и в двух подвалах `fastField` действительно стоял и ничего не делал.

Теперь сторож находит обёртки прямо в файле и идёт по цепочке до исходника.

**Проверено мутацией:** вернул `fastField` в `EstimateFormFooterLeft` — сторож
упал с точным адресом `EstimateFormFooterLeft.tsx:10 → <EstimateMsgFormGroup
fastField>`. Раньше это имя он не видел вовсе.

Заодно в список добавлено `inputProps` у поля ввода — пустое `inputProps={{}}`
стояло в окне учёта времени.

## 8. Что убрано осознанно

- `onDrop={null}` и `onDeleteFile={[]}` на двух вкладках вложений — оба
  свойства не делали ничего;
- `intent` у показчика всплывающих сообщений — окраска задаётся у отдельного
  сообщения, а не у показчика;
- `tableState` в разборе поставщика ставок налога — его никто не передаёт и
  никто не читает;
- `fastField` у двух групп полей — их читает поле внутри, а не группа.

Отдельно помечено, но **не тронуто**: область перетаскивания разбирает
`onDrop`, но наружу о новых файлах не сообщает — внутри свой обработчик.
Сегодня это ничего не меняет (оба места передавали `null`), подключение —
отдельная работа.
