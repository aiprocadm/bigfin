# Bigfin — Дорожная карта v47 «Хвост сторожей и готовность к CI» — 2026-09-01

Карта v46 закрыта и влита (#371). Она оставила задел: **шесть серверных
сторожей** записывают чтение файла по-своему, и общий приём к ним не
применён. Карта закрывает этот хвост и проверяет, готов ли продукт к
возвращению автоматических проверок.

Поручение владельца: «прими наиболее эффективное решение и продолжай
по ТЗ».

---

## 1. Что дала разведка

### Находка 1. «Пропущено автоматикой» ≠ «болен»

Шесть сторожей разобраны по одному — и половине лечение не нужно вовсе:

| Сторож | Что читает | Лечить? |
|---|---|---|
| `exchangeRateGuards` | исходник трансформера | **да** |
| `AuthMail.subscriber` | исходник подписчика | **да** |
| `deleteCustomerLinkedCreditSubscriberErrors` | исходник подписчика | **да** |
| `mail-translations` | `i18n/*/mail.json` | нет |
| `pdf-translations` | `i18n/*/pdf.json` | нет |
| `notificationPlural` | `i18n/*/notifications.json` | нет |

Три последних читают **словари в JSON**, где комментариев не бывает.
Применить к ним приём — значит сделать вид, что чинишь, ничего не меняя.
Это продолжение урока карты v46: механическая правка по списку делает
сторожа не строже, а бессмысленнее.

Почему автоматика их не узнала — тоже понятно: у всех шести чтение файла
записано в несколько строк, и правка искала однострочную запись.

### Находка 2. Продукт к возвращению CI готов

Процессы GitHub Actions выключены с августа. Раз их вот-вот включат, стоило
проверить: пройдут ли они? Шаги процесса «Tests» повторены вручную:

| Шаг процесса | Результат |
|---|---|
| `pnpm --filter @bigfin/server test` | **2281 тест / 340 наборов** — зелено |
| `pnpm --filter @bigfin/webapp test:run` | **959 тестов / 112 файлов** — зелено |
| `node packages/webapp/scripts/lang-check.js` | 4236 ключей, расхождений **0** |

**Чего проверить нельзя.** Процессы просят версию Node из `.nvmrc` — это
18.16.1 (карта v42). На сервере разработки стоит только v24.18.0, и все
прогоны идут на нём. Совпадение поведения двух версий здесь не проверено —
это и будет первым, что покажет первый настоящий прогон CI.

---

## 2. Решения, принятые по поручению

**Решение А. GitHub Actions — включить, но включить не смог.**
Дата, назначенная владельцем («до сентября»), наступила. Замер: репозиторий
приватный, значит минуты платные; остаток минут посмотреть не удалось —
для этого нужен доступ к счёту, которого у меня нет и который я не просил.
Само включение — правка настроек репозитория — **заблокировано
ограничениями моей среды**. Действие остаётся за владельцем: одно движение
в настройках, после него процессы подхватят правку карты v42 сами.

**Решение Б. Dependabot оставить на паузе.**
Он живёт в том же лимите минут (до 10 запросов на изменение в неделю, у
каждого свои прогоны), а остатка лимита я не вижу. Разумный порядок —
сперва включить обычные проверки, посмотреть недельный расход, и только
потом возвращать Dependabot. Отмена паузы — переименование одного файла,
дело минуты.

## 3. Что сделано

Три сторожа, читающие исходный код, переведены на действующий код. Три,
читающие словари, оставлены как есть — с записью почему.

### Проба

Опыт тот же: закомментировать в продукте строку, ради которой сторож
поставлен.

| Сторож | До карты | После |
|---|---|---|
| подписчик кредит-ноты не глушит ошибки | зеленел | **ловит** |

### Задел

- **Шесть разделов из девяти не ищутся** (задел карты v43): кредиты, долги,
  зарплата, дивиденды, бюджеты, платёжный календарь. Механизм готов —
  каждый стоит колонки в модели, параметра в запросе и четырёх строк на
  витрине.
- **Первый прогон CI** после включения стоит прочитать целиком: это первая
  проверка продукта на Node 18 за всё время, что прогоны идут вручную.

### Числа

- сервер: **2281 тест / 340 наборов** — зелено; `tsc` чист
- витрина: **959 тестов / 112 файлов** — зелено, не менялась
- продукт не менялся ни одной строкой: карта правит только проверки
