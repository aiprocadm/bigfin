Карта v38 закрыта целиком (#363): печать работает при запуске по

Открытых вопросов у владельца нет. GitHub Actions по-прежнему выключены до

---

## 1. Что дала разведка

Разведка вернулась туда, откуда её увёл прошлый заход, — к **поиску в
шапке**. Он есть на каждом экране, и им ни одна карта не занималась.

### Находка 1. Счёт покупателю ищется хуже всех документов

Живой замер (запросы к своему серверу на базе стенда):

| Запрос на экране счетов | Найдено |
|---|---|
| «СЧ-001» (номер счёта) | 1 |
| «100000.000» (сумма счёта) | 0 |
| «Ромашка» (клиент, у которого 5 счетов) | 0 |

Причина в коде — у счёта покупателю поля поиска **закомментированы**:

```ts
static get searchRoles(): ISearchRole[] {
  return [
    { fieldKey: 'invoice_no', comparator: 'contains' },
    // { condition: 'or', fieldKey: 'reference_no', comparator: 'contains' },
    // { condition: 'or', fieldKey: 'amount', comparator: 'equals' },
  ];
}
```

Замер по всем 17 моделям с поиском: **счёт покупателю — единственный
документ, который ищется по одному полю**. Соседи ищут по трём: счёт
поставщика, чек, смета, кредит-нота, возврат поставщику, оплаты — «номер,
ссылка, сумма». Проверено живьём: счёт поставщика по сумме «50000.000»
находится, счёт покупателю по своей сумме — нет.

Оба поля у счёта настоящие: `reference_no` лежит в своей колонке, а
`amount` в описании модели указывает на колонку `balance` — то есть
включение ролей ничего не сломает.

### Находка 2. Экран не говорит поиску, где человек стоит

Вид записей для поиска объявляет сам маршрут (`defaultSearchResource` в
реестре `routes/dashboard.tsx`). Замер: **из 117 маршрутов объявляют 63, а
54 молчат** — и на них поиск ищет «Клиентов», кто бы где ни стоял.

Среди молчащих — все новые разделы (кредиты, долги, сделки, зарплата,
дивиденды, основные средства, бюджеты, заявки на оплату, платёжный
календарь, распределение затрат, финмодель, статьи учёта), все отчёты,
расходы, налоговые ставки, банковские правила, интеграции и сама главная.

Живьём: открываю «Кредиты», печатаю «Кредит» → «Ничего не найдено», а
рядом подпись — «Клиенты».

Два маршрута объявляют вид **неверно**:

- `/items/import` объявляет «Клиентов» вместо позиций;
- `/financial-reports/general-ledger` объявляет `INVENTORY_ADJUSTMENT` —
  такого вида в продукте нет вовсе, значение выходит пустым, и экран молча
  оказывается в общем списке молчащих.

### Находка 3. Подпись обещает больше, чем поиск умеет

В шапке написано «Поиск по контрагентам, счетам…», и человек читает это
как «ищу везде». На деле поиск смотрит **один вид записей за раз** —
тот, что выбран кнопкой в окне. Отсюда и «Ничего не найдено» на экране
счетов при вводе имени клиента: искали среди счетов, а имя клиента там
не ищется.

## 2. Фаза «Поиск, который ищет не там» — срезы

1. **С1 — счёт покупателю ищется как все документы.** Включить поиск по
   ссылке и сумме. Сторож: у документов одинаковый набор полей поиска, а
   закомментированных полей поиска не бывает.
2. **С2 — экран говорит поиску, где человек стоит.** Починить два неверных
   объявления. Сторож: объявленный вид записей обязан существовать и быть
   тем, который поиск умеет искать.
3. **С3 — поиск не обещает лишнего.** Подпись честная, а пустой ответ
   говорит, СРЕДИ ЧЕГО искали и что вид можно переключить.

Порядок: С1 → С2 → С3.
Каждый срез: красный тест → правка → полные прогоны → живая проба → PR с
числами.

---

## 3. Что сделано

### С1 — счёт покупателю ищется как все документы

Поля поиска по ссылке и сумме включены: счёт покупателю ищется по номеру,
ссылке и сумме — как счёт поставщика, чек, смета, кредит-нота и оплаты.
Оба поля указывают на настоящие колонки (`amount` в описании модели ведёт
на колонку `balance`, где и лежит сумма счёта).

Сторож `documentsSearchFields` держит правило на всех восьми документах:
номер, ссылка и сумма — и **закомментированных полей поиска не бывает**.

**Почему поля были закомментированы.** Включить их «в лоб» не давала
проверка типов: в описании `ISearchRole` не было поля `condition`, которым
поля связываются как «или». Соседние документы объявляют свои роли **без
указания типа** — у них это поле проходит молча. То есть тип был неполным,
а закомментированные строки — след от попытки включить поиск и упереться в
него. Тип дополнен, все документы теперь описываются одинаково.

**Урок про сторожа.** Первая редакция проверки читала весь блок
`searchRoles` целиком — и зеленела на неисправном продукте, потому что
находила `reference_no` и `amount` внутри комментариев. Проверка смотрит
только действующие строки.

### С2 — экран говорит поиску то, что поиск понимает

Починены два маршрута: ввоз позиций объявлял «Клиентов» вместо позиций, а
Главная книга — `INVENTORY_ADJUSTMENT`, вида с таким именем в продукте нет
вовсе (значение выходило пустым, и экран молча попадал в поиск по
клиентам). Теперь Главная книга ищет среди проводок.

Сторож `searchResourceDeclared`: объявленный вид записей обязан
существовать И быть тем, который поиск умеет искать (есть адрес запроса и
разбор ответа). Проверен на исходном грехе — краснеет на
`INVENTORY_ADJUSTMENT`.

### С3 — поиск не обещает лишнего

Подпись в шапке была зашита строкой прямо в разметке — «Поиск по
контрагентам, счетам…». Теперь она берётся из словаря и называет тот вид
записей, среди которого поиск и правда будет искать: «Поиск: счета
покупателям».

Пустой ответ вместо одинокого «Ничего не найдено.» говорит, среди чего
искали, и подсказывает, что вид записей переключается кнопкой.

Общий помощник `searchScopeLabel` — один на подпись и на пустой ответ;
неизвестный вид не превращается в «undefined» на экране.

### Что осталось поиску (задел, не в этой карте)

- **Документы не ищутся по имени контрагента.** Самый частый способ, каким
  человек ищет («счета Ромашки»), не работает ни у одного документа.
  Механизм поиска умеет только колонки своей таблицы: соединений с другими
  таблицами в `DynamicListing` нет вовсе — нужна новая машинерия.
- **Новые разделы поиску неизвестны.** Кредиты, долги, сделки, зарплата,
  дивиденды, основные средства, бюджеты, заявки, платёжный календарь ищутся
  никак: у их списков нет ни поля поиска на сервере, ни вида записей на
  витрине.

### Находка живой пробы, вынесенная в следующую карту

Проверяя срез С2 на экране Главной книги, я обнаружил, что **экран
недостижим**: и по прямой ссылке, и по ссылке из раздела отчётов человек
молча оказывается на главной. То же на сборке стенда — значит, это
продукт, а не моя правка.

Причина: режим интерфейса. В режиме «бизнес» шесть экранов
(`/manual-journals`, `/make-journal-entry`, `/transactions-locking` и три
отчёта — Главная книга, Оборотно-сальдовая, Журнал) прячутся, и страж
`useAccountantOnlyRouteGuard` заменяет адрес на `/`. Меню такие пункты
прячет (карта v34), а **раздел отчётов их по-прежнему предлагает** — и
подмена происходит без единого слова, хотя у продукта уже есть правило
«выключенный раздел объясняет себя» (карта v36).
