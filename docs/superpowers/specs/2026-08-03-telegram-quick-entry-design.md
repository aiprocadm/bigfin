# ㉓ Ввод операций через Telegram-бота — дизайн

Дата: 2026-08-03. Дорожная карта v5 §5 п. 6 (доводка частичных), подпункт ㉓.

## 1. Что есть сейчас

Telegram работает **только на выход**: канал уведомлений (`TelegramChannel`),
привязка бота (`ConnectTelegram`: токен + `chat_id` в настройках тенанта,
группа `notifications`), клиент с `sendMessage`/`getUpdates`
(`TelegramApiService`). Входящие сообщения не читаются.

## 2. Зачем

Основатель пользуется продуктом сам и ценит мобильность. Записать расход
«на ходу» сейчас можно только открыв веб-приложение и заполнив форму.
Одно сообщение боту — самый быстрый путь: «−1500 такси».

## 3. Объём

**В объёме:** приём сообщений из привязанного чата, разбор в операцию,
создание записи в конвейере «Разбор» ⑨ (там же, где выписки и банк-API),
ответ пользователю подтверждением, выбор счёта по умолчанию, флаг
`telegram_quick_entry`.

**Вне объёма:** категоризация по правилам (для этого есть «Разбор»),
фото чеков, диалоги-уточнения, вебхук (см. §4), несколько чатов на тенанта.

## 4. Как получаем сообщения: опрос, не вебхук

Вебхук требует публичного HTTPS-адреса у каждой установки и общего
эндпоинта, а значит — реестра `chat_id → тенант` в system-схеме.
Опрос (`getUpdates`) уже используется при привязке, не требует ни публичного
адреса, ни новых системных таблиц: токен и так лежит per-tenant.

Схема — как у уведомлений (`NotificationsCron`): крон обходит собранных
тенантов и ставит по задаче в очередь; вся работа с данными тенанта —
внутри обработчика. Периодичность — каждые 5 минут.

Смещение (`last update_id`) хранится в настройках тенанта
(`telegram_last_update_id`), чтобы одно сообщение не обработалось дважды:
Telegram отдаёт апдейты, пока их не подтвердили смещением.

Дополнительно — ручной эндпоинт «получить сейчас», чтобы не ждать крон при
проверке и при первом использовании.

## 5. Разбор сообщения

`utils/parseQuickEntry.ts` — чистая функция `parseQuickEntry(text)`:

```
-1500 такси            → расход 1500, «такси»
1500 такси             → расход 1500, «такси»   (умолчание — расход)
+50000 оплата клиента  → приход 50000, «оплата клиента»
1 500,50 обед          → расход 1500.5, «обед»
-1500                  → расход 1500, без описания
```

Правила: первое число — сумма (пробелы-разделители и запятая допустимы),
знак `+` делает приход, `-` и отсутствие знака — расход (расходы вводят
чаще); остаток строки — описание. Команды (`/start`, `/help`) и строки без
числа операциями не считаются: на `/help` бот отвечает подсказкой, на
остальное — сообщением «не понял, пример: −1500 такси».

Дата операции — сегодняшняя (по часовому поясу организации мы не гадаем:
берём дату сервера, это MVP; уточнение даты — ручная правка в «Разборе»).

## 6. Настройки и создание операции

Новые ключи в группе `notifications` (там же, где токен бота):

| Ключ | Смысл |
|---|---|
| `telegram_last_update_id` | смещение обработанных апдейтов |
| `telegram_entry_account_id` | счёт Bigfin для операций из Telegram |

Счёт не задан → операции не создаются, бот отвечает «сначала выберите счёт
в настройках»: молча писать не туда нельзя.

Операция создаётся через тот же `CreateUncategorizedTransactionService`,
`externalId = telegram:<update_id>` — повторная обработка того же апдейта
ничего не задваивает.

Ответ в чат: «Записал: расход 1500 ₽ — такси» либо причина отказа.

## 7. Безопасность

Обрабатываются сообщения **только из сохранённого `chat_id`** —
посторонний, узнавший имя бота, ничего записать не сможет. Сообщения из
других чатов игнорируются молча (без ответа, чтобы не подтверждать
существование бота).

## 8. API и фронт

- `POST /notifications/telegram/entries/pull` — забрать сейчас (право
  `manage all`, за флагом): `{ imported, skipped }`.
- Настройка счёта — в существующую карточку Telegram на странице
  уведомлений: выпадающий список денежных счетов.
- i18n парно en/ru, ключи `notifications.telegram.entry.*`.

## 9. Тестирование

- Разбор: все примеры §5, команды, мусор, суммы с пробелами и запятой.
- Сервис: создание операции, пропуск чужого чата, отсутствие счёта,
  повторный апдейт (дедуп), продвижение смещения.
- Живой прогон: локальный HTTP-сервер, притворяющийся `api.telegram.org`
  (адрес API выносится в конфиг `telegram.apiBase`, по умолчанию боевой) —
  полный цикл «сообщение → операция в БД → ответ в чат» без реального бота.
  Реальный бот требует токена от @BotFather; это ручная приёмка владельцем.

## 10. Порядок работ

1. Разбор сообщения + тесты.
2. Конфиг `telegram.apiBase`, смещение и счёт в настройках.
3. Сервис приёма + дедуп + ответы, тесты на моках.
4. Крон + очередь + ручной эндпоинт.
5. Фронт: выбор счёта, кнопка «Забрать сейчас», i18n.
6. Живой прогон с локальным фейковым Telegram.
