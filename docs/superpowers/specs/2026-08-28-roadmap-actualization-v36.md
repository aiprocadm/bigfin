# Bigfin — Дорожная карта v36 «Выключенный раздел молчит» — 2026-08-28

Карта v35 закрыта целиком (#360): выгрузка отчётов отдаёт числа, а не
подписи; выгрузка не падает на прямом запросе. Открытых вопросов у
владельца нет. GitHub Actions по-прежнему выключены до сентября, проверки
гоняются вручную и приводятся числами в PR.

---

## 1. Что дала разведка

Разведка впервые прошла **интеграции** — единственную область, куда я не
заглядывал: МойСклад, импорт и выгрузка 1С, Дзенмани, CRM, эквайринг,
маркетплейсы.

Здоровым оказалось: экраны говорят по-русски и объясняют себя одной
фразой («Односторонняя синхронизация сделок и контрагентов из вашей CRM
в Bigfin»); поля дат после карты v32 — поля продукта; CRM просит ровно
то, что человек берёт в своей CRM (адрес вебхука, поддомен, токен).

Нашлось две вещи.

### Линия 1 (главная). Выключенный раздел показывает белую страницу

Открываю «Эквайринг» по прямой ссылке — **пустой экран**. Ни заголовка,
ни объяснения, ни ошибки. В консоли браузера: сервер ответил `403`.

Так устроены все экраны за флагом модуля:

```tsx
if (!featureCan(Features.Acquiring)) return null;
```

Замер по витрине: **21 экран целиком гаснет** таким образом (ещё шесть
мест гасят часть страницы — кнопку или блок, это законно).

Меню такие пункты прячет — карта v34 это починила. Но белую страницу
человек всё равно увидит: по закладке, по ссылке из письма или переписки,
или просто оставив вкладку открытой, когда модуль выключат в настройках.

Пустой экран не отличить от поломки продукта. Правильный ответ короткий:
сказать, что раздел выключен, и показать, где включить —
«Настройки → Модули» (`/preferences/modules`).

### Линия 2. Продукт просит внутренние номера руками

В выгрузке в 1С поле называется **«ID денежного счёта Bigfin»** — простая
строка ввода, без подсказки и без списка. Человеку неоткуда взять это
число: внутренний номер счёта нигде в интерфейсе не показан.

Замер: та же подпись стоит на **трёх экранах** — выгрузка в 1С, импорт
Дзенмани, синхронизация с банком. При этом готовый выбор счёта в продукте
есть и используется на десятках экранов.

Хуже того, в «Распределении затрат» ключ «Ручные доли» вводится **JSON-ом**
в моноширинном поле:

> Доли (ID сделки → вес) · подсказка: «JSON, напр. ID сделки → вес» ·
> ошибка: «Введите корректный JSON»

Продукт нацелен на предпринимателя без бухгалтерского образования. JSON и
внутренние номера — это язык разработчика, а не пользователя.

## 2. Фаза «Выключенный раздел молчит» — срезы

1. **П1 — выключенный раздел объясняет себя.** Общий экран вместо пустоты:
   заголовок, объяснение и кнопка «Настройки → Модули». Применяется ко всем
   экранам, которые гасли целиком. Сторож: экран за флагом не возвращает
   пустоту.
2. **П2 — счёт выбирается из списка.** Три экрана интеграций переходят с
   ввода внутреннего номера на обычный выбор счёта.
3. **П3 — доли задаются строками, а не JSON.** «Ручные доли» — выбор
   сделки и вес строками, с кнопкой «добавить»; JSON исчезает из
   интерфейса.

Порядок: П1 → П2 → П3.
Каждый срез: красный тест → правка → полные прогоны → живая проба на
собранной витрине → PR с числами.

## 3. Что сделано

### П1 — выключенный раздел объясняет себя

Общий экран `ModuleDisabled`: заголовок «Раздел выключен», объяснение и
кнопка «Открыть настройки модулей». Заменил `return null` на **21 экране**.
Сторож `moduleDisabledSpeaks` не даёт экрану за флагом снова погаснуть.

Живая проба вскрыла вторую половину задачи: поверх объяснения выскакивала
красная плашка **«У вас нет прав на доступ к этой странице»**. Замер:
**20 экранов из 21** спрашивают сервер ДО проверки флага — иначе ломается
порядок хуков. Сервер отвечает `403`, и витрина на любой `403` показывала
отказ в правах.

Корень оказался на сервере: страж модулей бросал `ForbiddenException` с
одним лишь текстом, и машинной приметы у ответа не было. Теперь отказ
несёт тип `FEATURE_DISABLED` и имя модуля, а витрина по нему молчит —
причина уже написана на экране. Права ни при чём: модуль включается
самим человеком в настройках.

### П2 — счёт выбирается из списка

`CashAccountField`: список денежных счетов (касса и банк) по названию с
кодом. Заменил ввод «ID денежного счёта Bigfin» на трёх экранах —
выгрузка в 1С, импорт Дзенмани, импорт выписки из банка. Подписи в обоих
языках больше не говорят про ID.

Живьём: список отдал 4 счёта («10001 — Расчётный счёт» и другие), выбор
счёта → «Скачать» → файл `1c_export.txt` скачался.

### П3 — доли задаются строками

`ManualSharesField`: строка = сделка из списка + вес числом + доля в
процентах, которую этот вес даёт. Кнопки «Добавить долю» и «Убрать
строку». JSON и слово «ID» ушли из подписей и из ошибок.

Живьём: два веса 1 и 3 показали «25 %» и «75 %», в базе сохранилось
`{"1": 3, "2": 1}`.

**Находка живой пробы.** Правило без сроков не сохранялось ВООБЩЕ: форма
слала пустую строку в дату, база отвечала `ER_TRUNCATED_WRONG_VALUE:
Incorrect date value: ''`, приходила ошибка 500. Незаполненный срок теперь
уходит как «не задано» (`withoutEmptyDates`).
