## 1. Приёмка фазы v8 на свежей организации

Фаза проверялась не по коду, а живьём: заведена **новая организация** (как у
настоящего новичка — регистрация, подтверждение почты, создание организации),
в неё приглашён человек с ролью «Сотрудник», и за него прожит обычный рабочий
день.

**Часть первая — работа должна идти.**

| Действие сотрудника | Итог |
|---|---|
| открыть список покупателей | ✅ 200 |
| завести покупателя | ✅ 201 |
| получить подсказку контрагентов | ✅ 200 |
| завести позицию (услугу) | ✅ 201 |
| выписать счёт покупателю на 20 000 ₽ | ✅ 201 |
| принять оплату по счёту | ✅ 201 |
| увидеть свои счета | ✅ 200 |

**Часть вторая — чего роль не давала, должно быть закрыто.** Шестнадцать
действий: банковские операции, правила разбора выписки, склады и их включение,
валюты, статьи учёта, категории товаров, реквизиты организации, шаблоны печати,
импорт, бюджеты, плановые операции, роли, закрытие периода, подписка на
продукт, эквайринг.

**Все шестнадцать отклонены.** Отдельно проверено, что отказ идёт **по праву**,
а не потому, что модуль выключен: владелец включил бюджеты и платёжный
календарь, после чего сотрудник получил «нет права», а не «модуль выключен».
Владелец на тех же ручках доходит до дела.

**Вывод: фаза v8 подтверждена на чистых данных. Новых дефектов приёмка не
нашла.**

## 2. Что дала разведка этой итерации

Шаг П1 закрыл **запись**: из 305 записывающих ручек каждая либо спрашивает
право, либо объявлена открытой с причиной, либо имеет собственную проверку.

Следующий естественный вопрос — **чтение**. Роль «Сотрудник» задумана как
повседневная работа с документами, а не как доступ ко всей финансовой картине
организации. Проверка живьём за приглашённого сотрудника:

| Отчёт | Видит ли сотрудник |
|---|---|
| Баланс | 🔒 закрыт |
| Прибыли и убытки (ОПиУ) | 🔒 закрыт |
| Движение денег | 🔒 закрыт |
| Главная книга | 🔒 закрыт |
| Журнал операций | 🔒 закрыт |
| Дебиторка и кредиторка по срокам | 🔒 закрыты |
| **Оборотно-сальдовая ведомость** | 👀 **видит** |
| **Остатки по покупателям и поставщикам** | 👀 **видит** |
| **Обороты по покупателям и поставщикам** | 👀 **видит** |
| **Продажи по позициям** | 👀 **видит** |
| **Оценка склада** | 👀 **видит** |

**Семь отчётов из шестнадцати открыты.** Разметка отчётов сделана меньше чем
наполовину: из восемнадцати отчётных контроллеров право спрашивают семь.

Показательнее всего пара «Баланс закрыт — оборотно-сальдовая ведомость
открыта»: ОСВ показывает обороты и остатки **по всем счетам организации**, то
есть ту же картину, только подробнее. Закрытая парадная дверь при открытой
задней.

## 3. Долг, вскрытый этой разведкой (новое в v9)

Порядок — по риску.

| № | Что | Почему важно | Объём |
|---|---|---|---|
| **В1** | **Половина отчётов не спрашивает права** | Приглашённый человек видит оборотно-сальдовую ведомость, обороты по всем контрагентам и оценку склада — всю финансовую картину, хотя роль давала только свои документы | Разметить одиннадцать отчётных контроллеров существующими правами `Report`; там, где права нет, — решение владельца |
| **В2** | **Действие без проверки, что документ есть** | Письмо по счёту и напоминание о долге по **несуществующему** документу отвечают «принято» (200/201) и уходят в очередь. Пользователь считает, что письмо отправлено | Проверять существование до постановки в очередь; найдено на письмах и напоминаниях, надо пройти весь класс |
| **В3** | **Подсказка контрагентов не отбирает по праву** | Роль, которой доверены только поставщики, видит в подсказке и покупателей с их долгами. Сейчас лучше прежнего (было — видно всем), но не точно | Отбор внутри подсказки по тому же праву, что и списки |
| **В4** | **Оплата счёта по ссылке лежит за входом** | Ссылка задумана для покупателя снаружи, но ручка требует входа в систему — значит поток нерабочий либо задуман иначе | Сначала ответ владельца: нужен ли внешний поток оплаты |
| **В5** | **Автопроверки на GitHub не работают** | Хвост v7: восемь сторожей фазы v8 и все прежние тесты гоняются только вручную. Упирается в оплату аккаунта | Владельцу: Billing & plans |
| **В6** | **Роль всего одна** | «Сотрудник» — единственная урезанная роль. Механизм своих ролей есть, но в интерфейсе это редкий сценарий | Вопрос 11 карты v8, решение владельца |

## 4. Предлагаемая фаза: «Кто что видит»

Смысл фазы — чтобы **приглашённый человек видел ровно то, что ему показали**.
Прямое продолжение: v6 — верить цифрам, v7 — верить факту сохранения, v8 —
верить границам записи, v9 — верить границам показа.

**Рекомендованный порядок:**

1. **В1 — отчёты.** Самое крупное и самое понятное. Идти так же, как в П1:
   группой, с живой пробой за сотрудника и сторожем, который считает
   размеченные отчётные ручки и не даёт списку разъехаться.
2. **В2 — действие без проверки существования.** Класс дефектов, а не одна
   ручка: письма, напоминания, постановка в очередь. Начать с реестра мест.
3. **В3 — отбор в подсказке.** Небольшая, но честная доводка П1.
4. **В4 и В6** — только после ответов владельца.

**Что НЕ делать сейчас**: тяжёлые банковские интеграции, нативный клиент,
консолидацию мультиюрлица (без изменений с v7 и v8).

## 5. Открытые вопросы владельцу

Из одиннадцати вопросов карты v8 закрыт один (№10 — справочники, взят мягкий
вариант). Остаются:

1. **Графический ребрендинг** — когда?
2. **ЭДО (Контур/Диадок)** — после первых клиентов с потребностью?
3. **Метод начисления** — нужен ли ручной перенос месяца отдельной операции?
4. **Telegram в РФ** — нужен ли резервный канал (VK Teams / MAX)?
5. **Анализ НДС / МойСклад** — развивать или «по запросу пользователей»?
6. **SMS/WhatsApp-напоминания дебиторам** — нужен провайдер.
7. **Перепроведение исторических документов с НДС** — массово одной кнопкой
   или по мере открытия документов? Инструмент готов (#194).
8. **Невозмещаемый НДС** — куда относить по умолчанию (сейчас в стоимость).
9. **Включать ли CI обратно** — упирается в оплату аккаунта GitHub.
10. **Роли гибче двух** — показывать ли создание своих ролей как обычную
    возможность интерфейса (вопрос 11 карты v8).
11. **НОВОЕ. Что должен видеть сотрудник из отчётов?** Предлагаю: свои
    документы и обороты по контрагентам — да; Баланс, ОПиУ, ДДС, Главную книгу
    и оборотно-сальдовую ведомость — нет. Это и есть содержание шага В1.
12. **НОВОЕ. Нужен ли внешний поток оплаты счёта по ссылке?** Сейчас ручка
    лежит за входом, то есть покупатель ею воспользоваться не может.
