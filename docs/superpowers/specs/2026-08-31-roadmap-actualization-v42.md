# Bigfin — Дорожная карта v42 «Сторожа, которых никто не сторожит» — 2026-08-31

Карта v41 отправлена (#366) и ждёт вливания: документы ищутся по имени
контрагента, расходы ищутся среди расходов. Эта карта берёт тему, которая
с ней не пересекается ни одним файлом, — **проверки, которые не
проверяют**. Хвост тянется с карты v40.

Поручение владельца: «прими решение самостоятельно и продолжай по ТЗ».

---

## 1. Что дала разведка

Разведка пошла не в продукт, а в его защиту. У проекта есть три слоя
проверок: git-хуки на машине, процессы GitHub Actions и сторожа в тестах.
Первые два не работали.

### Находка 1. Git-хуки не запускаются — и не у меня одного

При коммите git печатает подсказку:

```
hint: The '.husky/pre-commit' hook was ignored because it's not set as executable.
```

Первая мысль — особенность моей машины. Замер по самому репозиторию
говорит иначе:

```
100644 .husky/commit-msg
100644 .husky/pre-commit
```

Бита исполняемости нет **в самом репозитории**, а не в рабочей копии.
Значит хуки молча не работают у всех и на любой машине с самого их
появления. Коммит проходит, а запрет новых `@ts-nocheck` (карта v-guard,
`scripts/check-no-new-ts-nocheck.mjs`) и разбор сообщения коммита
(`commitlint`) не отрабатывают.

Замер последствий: из **40 последних коммитов 4** не проходят правило
сообщений (`subject-case`). Немного — но правило не действовало вовсе, и
это видно.

### Находка 2. Версия Node объявлена в двух вариантах

Источников правды четыре:

| Где | Что написано |
|---|---|
| `.nvmrc` | `18.16.1` |
| `package.json` → `engines` | `>=18.16.1` |
| `.github/workflows/e2e.yml` | `18.16.1` |
| остальные четыре процесса CI | `'18'` — любая свежая 18.x |

Плавающая «18» и фиксированная «18.16.1» — разные вещи: процессы
собирают продукт на одной версии, а `.nvmrc` обещает разработчику другую.
Расхождение молчаливое: пока обе версии ведут себя одинаково, никто
ничего не заметит.

### Находка 3. Сторожа нельзя описать словами

Найдена не разведкой, а самим срезом П1: как только хуки заработали, они
остановили **мой собственный коммит** — тот, что чинит хуки.

Причина: запрет новых `@ts-nocheck` искал **подстроку** в любой
добавленной строке. Комментарий «запрет новых `@ts-nocheck`» в описании
сторожа он считал нарушением.

Это хуже, чем неудобство. Сторож, о котором нельзя написать в
документации, обходят флагом `--no-verify` — и тогда он не сторожит
вовсе. Директива TypeScript — это комментарий, который с неё и
НАЧИНАЕТСЯ; упоминание внутри фразы директивой не является.

### Находка 4 (не срез). Actions отключены на уровне репозитория

```
GET /repos/aiprocadm/bigfin/actions/permissions → {"enabled": false}
```

Причина записана в истории самим владельцем: «Dependabot на паузе до
возобновления лимитов Actions» — то есть выключены не по прихоти, а
из-за исчерпанных минут. Лимит сбрасывается 1 сентября, то есть завтра.

**Решение: сам не включаю.** Это настройка аккаунта владельца и его
деньги; дата ещё не наступила. Включение — одно движение в настройках
репозитория, и после него процессы CI подхватят правку среза П2.

## 2. Фаза «Сторожа, которых никто не сторожит» — срезы

1. **П1 — git-хуки действительно запускаются.** Вернуть бит исполняемости
   в самом репозитории. Сторож: хук без бита исполняемости не бывает.
2. **П2 — версия Node названа один раз.** Процессы CI берут её из
   `.nvmrc`. Сторож: процесс не пишет версию своими руками.
3. **П3 — сторож не путает упоминание с директивой.** Запрет ловит
   комментарий, который с директивы начинается, а не любое её упоминание.

Порядок: П1 → П2 → П3.

---

## 3. Что сделано

### П1 — git-хуки действительно запускаются

Бит исполняемости возвращён в индекс репозитория
(`git update-index --chmod=+x`), а не только в рабочую копию: иначе
починка осталась бы на одной машине.

### П2 — версия Node названа один раз

Все пять процессов CI перешли на `node-version-file: '.nvmrc'`. Теперь
версия живёт в одном файле: меняют её там — меняется везде.

`.nvmrc` намеренно не трогал. Он фиксирует 18.16.1, и это версия, на
которой проект целится собираться; на сервере разработки её нет (стоит
только v24.18.0) — расхождение среды записано хвостом ниже.

### П3 — сторож не путает упоминание с директивой

Правило заменено: вместо подстроки `@ts-nocheck` — комментарий, который с
неё начинается (`// @ts-nocheck`, `/* @ts-nocheck */`, ` * @ts-nocheck`),
с любыми пробелами и пояснением после. Знак диффа `+` снимается перед
проверкой — иначе строка начиналась бы с него и правило не сработало бы
никогда.

Скрипт разделён на библиотеку и команду: `findOffenders` экспортируется,
а запуск с `process.exit` происходит только при прямом вызове. Иначе тест
не мог его импортировать — скрипт завершал процесс прямо при импорте.
Тестов у скрипта не было вовсе; теперь их пять.

### Сторожа

Первые два среза закрыты одним новым сторожем `repositoryGuards.spec.ts` — первым
в проекте, который смотрит не на код, а на сам репозиторий:

- режимы файлов берутся из `git ls-files -s`, а не из рабочей копии:
  проверка рабочей копии зеленела бы у того, кто поправил права у себя,
  и краснела бы у всех остальных;
- список хуков читается перед проверкой — иначе она стала бы пустой и
  зелёной, если каталог переименуют.

### Живая проба

Хуки проверены не рассуждением, а попыткой сделать то, что они обязаны
запретить.

| Что пробовал | До правки | После правки |
|---|---|---|
| коммит файла с новым `// @ts-nocheck` | проходил | **остановлен**: «Уберите `// @ts-nocheck`…», `pre-commit hook exited with code 1` |
| коммит с сообщением «плохое сообщение без типа» | проходил | **остановлен**: `type may not be empty`, `commit-msg hook exited with code 1` |
| коммитов в истории мимо правила сообщений | **4 из 40** | правило действует |
| коммит файла, где про `@ts-nocheck` НАПИСАНО словами | **остановлен ложно** | проходит |
| коммит файла с настоящей директивой `// @ts-nocheck` | остановлен | **остановлен** |

Оба пробных коммита в историю не попали — проверялось именно то, что хук
их не пускает.

Правку процессов CI живьём проверить нельзя: Actions отключены (находка
4). Проверено то, что можно без них: YAML всех пяти процессов разбирается,
шаг `setup-node` остался ровно один в каждом, версия больше нигде не
записана руками.

### Хвосты

- **Actions включить 1 сентября** — решение владельца, дата наступает
  завтра. После включения процессы подхватят правку П2 сами.
- **Node 18.16.1 на сервере разработки отсутствует** (стоит v24.18.0).
  Прогоны идут на v24 и проходят целиком, но это не та версия, на которой
  собирает CI. Ставить 18.16.1 на общий сервер шести проектов без спроса
  не стал.
- **Задел поиску (из карты v41):** новые разделы поиску неизвестны —
  54 маршрута из 117 не объявляют вид записей.
