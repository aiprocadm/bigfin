# Bigfin — Дорожная карта v88 «Слой по семь» — 2026-09-17

Карта v87 влита (#422). Её задел по технической линии: 134 файла вне проверки
типов, ближайшее — слой по 7 замечаний, 25 файлов.

Взято: **слой «семь замечаний» целиком — 25 файлов**, а следом — все файлы,
которые от общих правок этой карты подешевели до пяти замечаний и ниже
(ещё 7).

**Про порядок работ.** Пока шёл срез, в `develop` влит PR #423: ТЗ заведено в
репозиторий (`docs/tz/MASTER.md`, `STATE.md`, `CONTINUE.md`), и фраза
«продолжай по ТЗ» теперь ведёт в `docs/tz/STATE.md`, а не в дорожные карты.
Линия «слепая зона типов» в новом порядке — источник №5 режима стабилизации и
названа там законной работой. Эта карта — последняя в прежней нумерации:
дальше очередь ведёт ТЗ, этап 1 «Навигация».

## 2. Настоящие поломки

Двадцать. Каждая сверена с кодом, с сервером или с исходником библиотеки, не
выведена из сообщения проверки типов.

**Д18. Поле «Ссылка» в двух формах не было связано с формой — введённое
пропадало.** В форме входящего платежа и в форме кредит-ноты стояло
`<InputGroup name={'reference_no'} />` — обычное поле ввода Blueprint внутри
`FFormGroup`. Группа полей детей с формой НЕ связывает: в её собственном коде
`FormGroup({children, ...props})` дети передаются насквозь, а `useField` берётся
только для метки и ошибки. Значит `reference_no` не попадал в значения формы ни
при создании, ни при правке — хотя поле есть и в начальных значениях, и в схеме
проверки, и в DTO сервера (`referenceNo`). У одного из двух мест рядом стояло
ещё и `fastField`, которого поле ввода Blueprint не знает вовсе. Заменено на
`FInputGroup` — как у соседей (кредит-нота поставщика, сверка операции).
**Вживую не проверено** — витрина стенда за паролем nginx; вывод по коду
библиотеки. Заведён сторож: `InputGroup` + `fastField` (см. §4).

**Д3. Массовое удаление категорий товаров было мёртвым в четыре слоя.** Кнопка
«Удалить» в панели действий открывала предупреждение
`item-categories-bulk-delete`, а его нет в реестре `ItemsCategoriesAlerts`;
файл предупреждения не импортировался нигде; он ждал действие
`requestDeleteBulkItemCategories`, которого не существует во всём коде; а на
сервере ручки массового удаления категорий нет — только удаление по одной
(`ItemCategory.controller`). Сверх того кнопка вообще не показывалась:
`itemCategoriesSelectedRows` нигде не заполняется. Мёртвый путь удалён целиком
(файл предупреждения, кнопка, обёртка `withAlertActions` в панели).

**Д5. Три формы раздела «Проекты» ничего не сохраняют.** Отправка объявляла
`onSuccess`/`onError` и на этом заканчивалась: запроса не было, а уведомление
об успехе показало бы пустое сообщение (`AppToaster.show({})`). Дописать
сохранение некуда — серверных ручек `projects/*` не существует ни одной, раздел
закрыт решением владельца (Р3 карты v16), а окна недостижимы: маршрута
`/projects` нет и ссылок на них тоже. Оставлены заглушками с честной пометкой;
отправка теперь снимает «сохраняю», чтобы кнопка не крутилась вечно.

**Д1. Отказ сервера в четырёх предупреждениях проектов выглядел успехом.**
`catch` разбирал `{ response: { data: { errors } } }` и не делал ничего, а
`finally` закрывал предупреждение — человек видел, что окно закрылось, и не
узнавал, что удаление не прошло. Заменено на `showApiError`, как у соседей.

**Д6. Семьдесят крючков сохранения не объявляли, что им передают.**
`useMutation((id) => …)` выводит вид переменных как «их нет вовсе» (`void`), и
место вызова `deleteTaxRate(taxRateId)` перестаёт сходиться по типам — но
молчит, пока окно с вызовом лежит в слепой зоне. Это третий случай класса
(смена тарифа — v82, отмена и возобновление подписки — v87), поэтому заведён
сторож (§4). Вид объявлен в 70 местах: 45 с `id`, 25 с `values`.

**Д16. `useUpdateEffect` не принимал зависимости.** Список по умолчанию
`dependencies = []` выводился как «пустой список чего угодно» (`never[]`):
любое место вызова со своими зависимостями не сходилось по типам. Объявлен
`DependencyList`.

**Д9. В переключателе счетов у каждого счёта показывалось «Операции 25».**
Число вшито в разметку: `intl.get('cash_flow_transaction.switch_item', { value:
'25' })`. Настоящего счётчика операций не отдаёт ни сервер, ни витрина — слова
`transactionsNumber` нет нигде, кроме этого файла. Подпись снята: пустое место
честнее выдуманной цифры. Заодно у списка появился `key` — его не было.

**Д2. Предупреждение об удалении налоговой ставки говорило по-английски.** Оба
абзаца были английским текстом прямо в разметке, мимо словаря, причём во втором
дыра: «Are you sure you want to delete ?». Заведён ключ
`tax_rates.alert.once_delete_this_tax_rate` (en + ru).

**Д10. В форме исходящего платежа потерян второй довод `defaultTo`.**
`defaultTo(preferredPaymentAccount)` вместо `defaultTo(preferredPaymentAccount,
'')` — без счёта по умолчанию поле уходило в форму пустотой (`undefined`) и
переставало быть управляемым. У соседней формы расходов записано правильно.

**Д4. Обёртка `withItemCategories` без своего отбора отдавала `undefined`.**
`return mapState ? mapState(mapped, state, props) : mapState` — в ветке «отбора
нет» возвращался сам отбор, то есть пустота. Теперь отдаётся собранное.

**Д13. Дыра в стороже карты v85: `fastField` и `shouldUpdate*` у
blueprint-овой группы полей.** Сторож «свойства, которых никто не читает» знал
про `fill`, `name`, `minimal`, но не про слова из обёрток над Formik. В коде
библиотеки их нет вовсе; одно живое место нашлось сразу — шапка формы расхода.
Правило расширено, место вычищено.

**Д8. Витрина читала три числа, которых не было в объявлении ответа.** Страница
импорта выписки показывает разбивку пропущенных записей (дубли, без
направления, не разобрано) — сервер их шлёт (`Import1CResult.dto`, инвариант
`skipped = duplicates + noDirection + unparsed`), а `Import1CStatementResponse`
на витрине перечислял только `imported` и `skipped`. Дописано.

**Д15. `theme.bpPrefix` не существовал для проверки типов.** Тему кладёт
`DashboardThemeProvider`: `defaultTheme` плюс своё поле `bpPrefix: 'bp4'`, а
объявление темы в `@emotion/react` пустое. Заведено расширение
`src/types/emotion.d.ts` — из-за этого одного поля не выходили из зоны все
файлы со стилями форм.

**Д17. Рамка перетаскивания файлов ссылалась на несуществующую библиотеку.**
`MantineColor`, `MantineRadius`, `LoaderProps`, `Factory` — виды из Mantine,
которой в проекте нет. Заменены своими. Там же сняты два мёртвых остатка:
`variant` (единственное упоминание в теле закомментировано) и `mod` — способ
Mantine ставить `data`-атрибуты, который наш `Box` не знает и который уезжал бы
в DOM неизвестным атрибутом; стили рамки завязаны на классы, а не на эти
атрибуты.

**Д12. Подсветка совпадения уезжала в свойство для строки.** У `MenuItem`
Blueprint `label` — строка, для разметки есть `labelElement` (это написано в
самом объявлении библиотеки). Так было в подсказке всеобщего поиска и у флажка
«Субсчёт» в окне счёта.

**Д19. Группа полей объявлена на одного ребёнка, а принимает нескольких.**
Пакет `@blueprintjs-formik` объявляет `children: React.ReactElement`, хотя
передаёт детей насквозь. Четыре места (полная сумма и выбор контрагента в двух
формах платежей) собраны в один прозрачный узел — разметка не изменилась.

**Д11. Таблица бланков печати объявляла пустой набор свойств.**
`interface BrandingTemplatesTableProps {}` — при этом компонент читает
`openAlert` и `openDrawer` от обёрток. Объявление собрано из их видов.

**Д7. Запасная ветка чтения ключа API не срабатывала никогда.** Сервер отдаёт
`{ key, id }` телом ответа, значит ключ лежит в `response.data.key`; ветка
`response.key` мертва. Снята.

**Д14. Разбор веток в `Choose` падал бы на нестандартном ребёнке.** Условие
читалось у любого ребёнка, включая строку и пустоту (`children.props.condition`).
Теперь ветками считаются только элементы. Там же сняты `propTypes` — React 18.3
их у функциональных компонентов игнорирует (как в карте v87).

**Д20. Полоса выполнения получала `value={null}`.** В коде библиотеки
`value == null` и отсутствие свойства — одна и та же ветка «идёт, срок
неизвестен»; свойство убрано.

**Сирота удалён:** `services/RemoteDataBinding.tsx` — класс из чужого шаблона
(формат OData, `$skip`/`$top`/`d.results`), обращается к полям `this.ajax` и
`this.baseUrl`, которых у него нет, и не используется нигде.

## 5. Честно

**Живой пробы не было.** Витрина стенда за паролем nginx. Д18 (поле «Ссылка»),
Д3 (кнопка категорий) и Д9 (подпись «Операции 25») проверены чтением кода
витрины, сервера и самих библиотек — не глазами. При первом доступе к стенду
проверять в этом порядке: ссылка в платеже → ссылка в кредит-ноте →
переключатель счетов.

**Поведение изменено осознанно в пяти местах:** поле «Ссылка» начинает
сохраняться (Д18); отказ в предупреждениях проектов становится виден (Д1);
подпись «Операции 25» исчезает (Д9); кнопка массового удаления категорий
исчезает (Д3); счёт по умолчанию в форме платежа перестаёт быть пустотой
(Д10). Остальное — объявления, на выполнение не влияющие.

**Раздел «Проекты» — 91 файл мёртвого кода.** Маршрут удалён, меню
закомментировано, ручек на сервере нет ни одной, окна недостижимы. Удаление
файлов раздела — отдельное решение владельца (записано ещё в карте v16); в этом
срезе они только выведены из слепой зоны и помечены.
