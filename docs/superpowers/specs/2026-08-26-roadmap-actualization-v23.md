## 1. Итог фазы v22 — одним абзацем

Продукт научился главному денежному разговору: спрашивает налоговый режим и
юрформу при создании организации, сам подставляет ставку НДС по режиму,

поля в camelCase). Обе починены, и из них выросли два инструмента приёмки —
`smoke-check.sh` и `new-org-check.sh`.

## 2. Что дала разведка этой итерации

Разведка смотрела продукт глазами человека с телефоном — основатель ценит
мобильность. Четыре догадки НЕ подтвердились, и это тоже результат:

- **вёрстка не расползается**: на ширине 390 px ни один из семи проверенных
  экранов не даёт горизонтальной прокрутки, а таблица позиций счёта
  прокручивается внутри своего блока, как и должна;
- **онбординг есть и толковый**: у новой организации «Первые шаги, 1 из 5»
  с понятными пунктами и отметками по настоящим данным;
- **скорость нормальная**: сводка о деньгах появляется за 0,75 секунды,
  запросы к серверу — по 100–130 мс;
- **потеря связи обработана**: показывается «error.network», а не пустой
  экран.

А нашлось вот что — и это, пожалуй, самое неожиданное за все карты.

### Линия 1 (главная). Во всём новом интерфейсе не работают отступы

В стилях **одной страницы** — `style/pages/register-organizaton.scss`,
формы регистрации организации — первым делом объявлен глобальный сброс:

```css
* {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}
```

Файл импортируется в общий `App.scss`, то есть правило действует на всё
приложение. А поскольку Tailwind 4 кладёт свои утилиты в каскадный слой
(`@layer utilities`), а этот сброс объявлен ВНЕ слоёв, он побеждает: по
правилам каскадных слоёв объявления вне слоёв сильнее любых объявлений
внутри слоя, независимо от специфичности.

Проверено на собранной витрине стенда (не в dev-режиме):

| Что | Результат |
|---|---|
| правило `.p-3` | есть, в слое `utilities`, `padding: calc(var(--spacing) * 3)` |
| правило `*` | есть, **вне слоёв**, `margin: 0; padding: 0` |
| итоговый `padding` у элемента с классом `p-3` | **0px** |
| `gap-3`, `rounded-md`, `text-sm`, `h-11` | работают (их в сбросе нет) |

То есть у всего нового интерфейса (D-redesign) молча отключены `p-*`,
`px-*`, `py-*`, `m-*`, `mx-*`, `space-*` — а `gap`, скругления, размеры
шрифта и высоты работают. Отсюда «полусобранный» вид: где вёрстка держится
на `gap` и `grid`, всё выглядит прилично, а где отступы внутри блока — всё
слипается.

### Линия 2. Следствие: по пунктам меню трудно попасть пальцем

Пункт бокового меню размечен как `px-3 py-2` — то есть должен быть около
36 px высотой. Фактически он **20 px**: `py-2` не действует. На телефоне
меню открывается во весь экран, и человек целится пальцем в полоски высотой
20 px, идущие вплотную одна к другой (проверено живьём: 47 видимых пунктов,
все ниже 44 px — рекомендованного размера цели касания).

Отдельно: кнопка «Быстрое создание» уже 44×44 — образец в продукте есть.

### Линия 3. Урок про измерения

Первые замеры я снимал с dev-сборки vite и получил ту же картину — но там
Tailwind вообще не генерировал утилиты отступов, то есть цифры совпали
СЛУЧАЙНО, по разным причинам. Правильный вывод получился только после
проверки на собранной витрине стенда. **Мерить интерфейс нужно на той
сборке, которую видит пользователь.**

## 4. Фаза «Интерфейс без отступов» — срезы

1. **О1 — вернуть отступы.** Ограничить глобальный сброс страницей, ради
   которой он написан. Живьём: у элемента с `p-3` отступ 12 px, пункт меню
   становится выше 20 px, легаси-страницы (списки, формы Blueprint) не
   разъезжаются.
2. **О2 — сторож на глобальные сбросы.** Тест по стилям: никакой файл не
   вправе объявлять `*`-сброс полей и отступов вне слоя. Проверить на
   исходном файле — он должен краснеть.
3. **О3 — цели нажатия на телефоне.** После О1 перемерить и поднять до
   44 px то, что осталось мелким: пункты меню, кнопки панелей действий в
   списках (32 px), круглые кнопки (36×36).
4. **О4 — демо живьём (решение 37).** Перенос из карты v22 без изменений.

Порядок: О1 → О2 → О3 → О4 (по решению).
Каждый срез: красный тест → правка → полные прогоны → живая проба **на
собранной витрине** → PR с числами.
