# Спецификация под-проекта: Полный редизайн (D) — Фазы 0+1+2

**Дата:** 2026-05-25
**Тип документа:** Spec под-проекта (графический ребрендинг + дизайн-система v1 + пилот)
**Статус:** Draft → ожидает review основателя
**Длительность:** 6-9 недель полной занятости (~2-3 календарных месяца)
**Место в roadmap:** Вставка между фазами основной [2026-05-22 fintablo-parity-roadmap](2026-05-22-fintablo-parity-roadmap.md). Это под-проект «D», явно зарезервированный как «Графический ребрендинг — отдельный под-проект, может быть вставлен между фазами».

---

## 1. Контекст и цели

### Контекст

Bigfin — самостоятельный продукт. Из исходной кодовой базы унаследован визуальный язык «корпоративный SaaS 2018»: BlueprintJS-компоненты, индустриально-серая палитра, плотные таблицы, термины бухгалтера. Эта визуальная подача противоречит позиционированию Bigfin (управленческий учёт для предпринимателя без бух. образования). Пока продукт визуально не имеет собственного лица, он не воспринимается как самостоятельный.

### Цели (в порядке приоритета)

1. **Идентичность.** Bigfin должен визуально перестать быть калькой исходного продукта и стать узнаваемым как самостоятельный продукт. Направление — **Bold Fintech** (Тинькофф / Revolut), не Fintablo.
2. **Технический долг.** 5 параллельных систем стилизации (SCSS + styled-components + emotion + xstyled/emotion + theme-ui) сводятся к одной (Tailwind 4).
3. **Совместная работа с Claude.** Стек, который Claude знает наизусть (Tailwind + shadcn/ui), резко увеличивает скорость solo-разработки.
4. **Дизайн-система как актив.** Все 16 под-проектов основной roadmap будут потреблять эту DS. Без неё каждый следующий под-проект будет ре-изобретать кнопки.

### Не-цели

- Не меняем бизнес-логику, серверную часть, схему БД.
- Не делаем финальный брендбук — только v1, достаточный для пилота. Бренд дозревает через 12 экранов.
- Не убираем BlueprintJS принудительно. Старые экраны остаются на BP, пока не приходит их очередь миграции.

## 2. Что входит / что НЕ входит

### Входит

- **Бренд v1:** палитра (тёмная + светлая как CSS-переменные), типографика (Inter Variable), радиусы, отступы, тени — токены в `tailwind.config.ts`.
- **Логотип v1.** Wordmark «Bigfin» + опциональный значок. Рабочий, не финальный.
- **Storybook 8** в `packages/webapp/` — запускается одной командой без бэкенда.
- **Tailwind 4 + shadcn/ui CLI** установлены без конфликта со старыми SCSS-файлами.
- **15 компонентов** в `packages/webapp/src/components/ui/` с Storybook-story для каждого.
- **Пилот: Login + Register + ForgotPassword** на новом стеке, в продакшене, заменяют старые auth-страницы.
- **README** в `packages/webapp/src/components/ui/README.md` (1-2 стр.): как добавлять компоненты, как именовать, как мигрировать.

### Не входит

- Миграция остальных экранов (Dashboard, Сделки, Settings) — это отдельный под-проект «D-Phase-3».
- Принудительное удаление BlueprintJS.
- Финальный брендбук (Notion-страница с гайдлайнами).
- Полированная светлая тема (dark — primary, light — best effort).
- Мобильное приложение (под-проект ⑬).
- Изменения в `packages/server/`.

## 3. Архитектура решения

**Ключевая идея:** две дизайн-системы сосуществуют в одном webapp-пакете. Старые экраны — на BlueprintJS, новые — на shadcn. Граница проходит **по файлам компонентов**, не по фиче-флагам.

### Структура папок (новое в `packages/webapp/src/`)

```
src/
├── components/
│   ├── ui/                        ← НОВОЕ. shadcn-компоненты, скопированные в проект
│   │   ├── button.tsx
│   │   ├── input.tsx
│   │   ├── card.tsx
│   │   └── README.md
│   ├── auth/                      ← НОВОЕ. Страницы пилота
│   │   ├── LoginPage.tsx
│   │   ├── RegisterPage.tsx
│   │   └── ForgotPasswordPage.tsx
│   └── ...                        ← Существующее. BP-компоненты не трогаем
├── styles/
│   ├── globals.css                ← НОВОЕ. @tailwind base + tokens
│   └── tokens.css                 ← НОВОЕ. CSS-переменные для бренда
├── style/                         ← Существующее SCSS. Остаётся для старых экранов
└── lib/
    └── cn.ts                      ← НОВОЕ. clsx + tailwind-merge утилита
```

### Изоляция стилей

- В `tailwind.config.ts` поле `content` ограничено только новыми папками (`./src/components/ui/**/*.tsx`, `./src/components/auth/**/*.tsx`). Tailwind не генерирует классы для BP-областей.
- shadcn использует CSS-переменные в `:root` и `.dark` — изолированы от BP.
- Существующие SCSS-стили подключаются после Tailwind base — их специфичность выше.
- Новые компоненты используют ТОЛЬКО Tailwind-классы. Никаких SCSS, styled-components, emotion.

### Storybook

Живёт в `packages/webapp/.storybook/`. Запускается `pnpm storybook` на `localhost:6006`. Не требует бэкенда. Импортирует `globals.css`. `stories`-glob ограничен `./src/components/ui/**/*.stories.tsx`.

### Маршрутизация

Через существующий `react-router` v5. Добавляются новые роуты `/auth/login`, `/auth/register`, `/auth/forgot-password`. Старые auth-роуты удаляются.

## 4. Фазы и последовательность

### Фаза 0 — Подготовка инфраструктуры (~1-2 недели)

**Цель:** Tailwind + Storybook работают, ничего не сломано.

1. Установить `tailwindcss@^4.0`, `@tailwindcss/vite`, `clsx`, `tailwind-merge`, `class-variance-authority`, `tailwindcss-animate`, `lucide-react`.
2. Создать `src/styles/globals.css` и `src/styles/tokens.css` (пока пустые с базовыми слоями).
3. Создать `src/lib/cn.ts`.
4. Установить Storybook 8: `pnpm dlx storybook@latest init`.
5. Установить shadcn CLI: `pnpm dlx shadcn@latest init` — отвечает на вопросы про tokens.
6. **Проверить:** `pnpm dev` запускает приложение, существующие экраны выглядят как раньше.
7. **Проверить:** `pnpm storybook` запускает Storybook на `localhost:6006`.

**Критерий завершения:** оба `pnpm dev` и `pnpm storybook` работают, существующее приложение визуально не изменилось.

### Фаза 1 — Бренд v1 + DS v1 в Storybook (~3-4 недели)

**Цель:** в Storybook есть «всё, что нужно для Login + Register», и оно соответствует Bold Fintech.

1. Зафиксировать токены v1 (раздел 6): записать в `tailwind.config.ts` и `tokens.css`.
2. Создать Storybook-страницы `Tokens`, `Typography`, `Colors`.
3. Скопировать через shadcn CLI 11 компонентов: `button`, `input`, `label`, `form`, `card`, `checkbox`, `separator`, `alert`, `sonner` (toast), `skeleton`, `tooltip`.
4. Создать кастомные компоненты: `Logo`, `Spinner`, `Link`, `AuthLayout`.
5. Кастомизировать каждый под Bold Fintech.
6. Написать `.stories.tsx` для каждого: все варианты, все состояния (default, hover, focus, disabled, error).

**Критерий завершения:** в Storybook видна работающая дизайн-система — её можно показать.

### Фаза 2 — Пилот Login/Register в продакшене (~2-3 недели)

**Цель:** при заходе на сайт виден Bold Fintech Login.

1. Собрать `LoginPage.tsx`, `RegisterPage.tsx`, `ForgotPasswordPage.tsx` из готовых компонентов в `src/components/auth/`.
2. Заменить роуты в `react-router` на новые.
3. Удалить старые auth-страницы (BP-версии).
4. Запустить `pnpm dev` — физически проверить в браузере (работает без бэкенда!).
5. Опционально: deploy на staging-домен.

**Критерий завершения:** на `localhost:4000/auth/login` виден Bold Fintech Login, формы валидируются, кнопка «Войти» отправляет запрос (в Network видно).

**Совокупная длительность 0+1+2:** ~6-9 недель полной занятости (~2-3 календарных месяца с учётом обучения).

### Палитра (светлая — best effort)

Инвертируем фон/текст, акцент жёлтый остаётся, но затемнённый (`#E5A800`). Финализация — в Фазе 1 при работе с Storybook.

- **Один шрифт:** Inter Variable (open source, отличная кириллица, fintech-стандарт).

- **Опциональный второй шрифт** (для лого / акцентного заголовка): JetBrains Mono или Geist Mono — решим в Фазе 1.

### Шкалы (стандартный Tailwind)

- Шрифты: `text-xs` (12px) → `text-4xl` (36px)
- Отступы: 4px-шаг
- Радиусы: `rounded` (4px), `rounded-lg` (8px, дефолт), `rounded-xl` (12px, карточки), `rounded-full`
- Тени: на тёмной — минимальные, только в focus-ring и hover-elevation

### Иконография

lucide-react, страйк 1.5px, размеры 16/20/24px.

## 8. Дизайн пилотных экранов

### Общий лейаут

**Десктоп (≥ 768px):**
- Двухколоночная сетка 50/50.
- Левая колонка (`#0A0E1A`): крупное `Bigfin`-wordmark + тэглайн, абстрактный геометрический pattern или blurred screenshot дашборда.
- Правая колонка (`#13182B`): форма по центру, max-width 420px.

**Мобильный (< 768px):**
- Однокол, форма в `Card`-обёртке.
- Лого над формой, левая колонка скрыта.

### Login — структура формы

```
Войдите в Bigfin              ← h1, text-3xl, font-semibold
Управляйте финансами бизнеса  ← subtitle, text-zinc-400

[ Email                     ] ← Input
[ Пароль              👁    ] ← Input + show/hide

☐ Запомнить меня    Забыли пароль?  ← Checkbox + Link

[      Войти      →           ] ← Button primary, yellow

────────── или ──────────       ← Separator

[  G  Войти через Google      ] ← Button secondary

Нет аккаунта? Зарегистрируйтесь ← Mute + Link
```

### Register

Добавляется поле «Имя» сверху, «Подтвердить пароль» снизу, чекбокс согласия с офертой. Без Google-варианта (опционально в Фазе 2).

### ForgotPassword

Только Email + кнопка «Отправить ссылку». После отправки — Alert «Письмо отправлено на ваш email».

### Валидация (zod-схемы)

- Email: правильный формат
- Пароль (Register): мин. 8 символов
- Confirm password: совпадает с password
- Сообщения на русском, под полем, через `FormMessage` после blur

### Состояния

- **Idle** → обычный вид
- **Submitting** → Spinner в кнопке, форма disabled
- **Server error** → красный Alert над формой
- **Network error** → Toast в верхнем правом углу
- **Success** → редирект на `/`

## 9. План миграции после пилота

После завершения этого под-проекта запускается **отдельный последующий под-проект «D-Phase-3»** со своей спецификацией.

### Предлагаемый порядок миграции

| Очередь | Группа экранов | Почему |
|---|---|---|
| 1 | Settings (Профиль, Организация, Подписка) | Много форм, паттерны Login повторяются |
| 2 | Onboarding-wizard | Изолированный флоу, низкий риск |
| 3 | Dashboard | Требует решённого Docker. Высокий импакт |
| 4 | Customers / Vendors lists | Первая миграция таблицы → добавляем `Table` в DS |
| 5 | Invoice list + Invoice detail | Самая сложная форма |
| 6 | Manual Journals, Plan of Accounts | Бухгалтерские (режим accountant) |
| 7 | Reports (ДДС / ОПиУ / Баланс) | Параллельно с под-проектом ④ |

### Принцип

**Один экран = один PR.** В рамках одного PR файл полностью переезжает с BP-компонентов на shadcn. Никаких половинчатых миграций. Откат = `git revert`.

### Анти-паттерн, которого избегаем

«Глобальная миграция Button» — НЕ делаем. Замена идёт только в файлах, которые в любом случае переписываются.

## 10. Сосуществование Blueprint ↔ новой системы

**Главное правило:** один файл-компонент использует либо ТОЛЬКО Blueprint, либо ТОЛЬКО shadcn.

### Технические гарантии

1. **Tailwind не загрязняет глобальный CSS** — `content` в `tailwind.config.ts` ограничен только новыми папками.
2. **shadcn CSS-переменные** в `:root` и `.dark` — изолированы от BP.
3. **BP-стили имеют выше специфичность** — SCSS подключается после Tailwind base.
4. **Storybook видит только новые компоненты** — `stories`-glob ограничен `./src/components/ui/**/*.stories.tsx`.

### Что НЕ делаем

- Не темизируем BP под Bold Fintech.
- Не делаем глобальный feature-flag UI v1 vs v2.
- Не оборачиваем shadcn в BP-API.

### Откат

`git revert <PR-hash>`. Файл возвращается к BP-версии, остальной код не страдает.

## 11. Критерии завершения под-проекта

Под-проект считается завершённым, когда:

1. `pnpm storybook` запускает Storybook на `localhost:6006`, в нём 15 компонентов с историями + страницы `Tokens`, `Typography`, `Colors`.
2. `pnpm dev` запускает приложение, страница `/auth/login` выглядит в Bold Fintech-стиле, валидируется через zod.
3. Страницы `/auth/register` и `/auth/forgot-password` работают.
4. Старые auth-экраны (BP) удалены из кода.
5. `pnpm typecheck` возвращает 0 ошибок.
6. `pnpm lang:check` возвращает 0.
7. Существующие e2e-тесты продолжают проходить.
8. `packages/webapp/src/components/ui/README.md` объясняет: как добавить компонент, как именовать, как мигрировать BP→shadcn.
9. Спецификация под-проекта «D-Phase-3» создана как драфт.
